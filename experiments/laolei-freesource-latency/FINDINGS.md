# 免费数据源探索 — 能否破 in-play 延迟劣势

owner: 老雷  last_review: 2026-06-09
**隔离实验, 不碰生产代码 (老板「别污染当前项目」)**

## 背景
in-play 方向交易判死的物理根因 = Goalserve 中继 bet365 落后 **2.3s**, 而 PM 在 ~0.3s 内被【直接看比赛的人/bot】重定价 → 我们永远追过期信号 = 逆向选择。老板让找**免费源**试能否破延迟劣势。

## 已测免费源 (curl 实测 2026-06-09)

| 源 | 可达 | 比分/状态 | 赔率(fair) | 覆盖 | ToS |
|---|---|---|---|---|---|
| **ESPN 隐藏 API** (`site.api.espn.com`) | ✅ 免费无 key | ✅ 好 (pre/in/post + score) | ❌ **空**(MLB 赛前/赛中都无 ML) | 主流(MLB/NBA/ATP), 不含 ITF 冷门 | 隐藏但常用, 边界 |
| **sofascore** (`api.sofascore.com`) | ⚠️ live 返 0(疑似封/无赛) | (有则好+广) | (有 1x2) | 广(含 ITF) | 非官方爬, ToS 风险高 |
| The Odds API | — | — | 有但 **限速 500/月≈16/天** 不够实时 | — | 官方免费但限速 |
| Pinnacle | 老板否决(memory no-pinnacle) | — | — | — | — |

## 核心发现 (诚实)
1. **免费【比分】源有** (ESPN 好用), 但**没有免费的实时【赔率/fair】源** —— 没 fair 就没法做"买低于 fair"的方向定价。
2. ESPN 无 odds → 要用它只能**自建定价模型**(score → 概率), 但博彩老张已判:我们的模型不比市场好(且 PM 已含 bet365)。这是"真模型 alpha"路 = 大工程, 不保证成。
3. **更深的墙不是数据源速度, 是 PM 市场效率**: PM 由直接看比赛的人重定价(~0.3s), **任何聚合 API(ESPN/Goalserve/sofascore)都慢于直接看** → liquid 盘上换源也追不上。免费源最多把 2.3s 缩到 ~?s, 仍 >0.3s。
4. **唯一可能的角度**: ESPN 的【final 检测】可能比 PM 结算快(PM 结算经 oracle 滞后数分钟) → 买已知赢家锁结算收敛。但 gap 仅 ~0.02(PM 看客早把赢家定到 0.98+), +EV 但太小、竞争激烈、量太少 → 到不了 +200u。

## 待测 (需 live 赛 + 并发 PM 对比)
`probe.sh`: 同时轮询 ESPN + Goalserve inplay 同一 live 赛, 比分变化时比时间戳 → ESPN 是否比 Goalserve 2.3s 快。**现无 live 赛(MLB 刚结束), 待 live 赛时跑。** 即便 ESPN 快, 仍需过 §3 的 PM 效率墙 + §2 的无 fair/无更优模型墙。

## 结论倾向
免费源探索**不明显解锁 +200u**: 有免费比分但无免费 fair; 深层墙是 PM 效率 + 我们无信息优势, 非单纯数据速度。换源把 2.3s→更快, 但仍追不上 PM 直接看客, 且没 fair 源。**若要继续: 唯一活路是"ESPN/免费比分 + 自建够好的预测模型"(真 alpha, 大工程, 不保证)**。
