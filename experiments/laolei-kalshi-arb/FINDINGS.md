# Kalshi × Polymarket 跨市场价差套利 — 可行性调研

owner: 老雷  last_review: 2026-06-09
**隔离实验, 不碰生产 (老板「别污染当前项目」)**

## 为什么这个方向值得看
跨市场套利赚的是**两个市场对同一事件的【分歧】**, 不拼速度 → 绕开我们 in-play 的死穴(数据源延迟)。**注: 老板纠正——我们服务器不慢(伦敦 3-6ms 到 CLOB), 速度劣势是【数据源】层(Goalserve 2.3s), 非基础设施。**

## 实测发现 (curl, 2026-06-09)
1. **Kalshi 公开 API 可达** (`api.elections.kalshi.com/trade-api/v2/`, 无需 auth 读行情)。
2. **有真实可交易价 + 深度**: BTC 日盘 orderbook 实有挂单 (no_dollars: 0.02×52528 等)。字段是 `*_dollars` 命名。
3. **类目与 PM 重叠**: Sports(MLB 队 Seattle/Tampa/Detroit、网球 Hurkacz)、Crypto(BTC)、Elections、Financials —— 都和 PM 有。

## 两道结构性可行性约束 (诚实)

### 约束 A — 执行: 司法管辖冲突 (关键)
- **Kalshi = 美国 CFTC 监管, 需美国 KYC**; **PM = 封禁美国用户**。**同一主体无法合法同时接入两边**。
- 机械上**两实体结构可锁套利** (美国实体持 Kalshi 一腿 + 离岸实体持 PM 另一腿; 锁差数学成立: 买便宜侧 YES + 买贵侧 NO → 任一结算锁正)。但: 双边资金分离占用、不能 net、双实体合规重、运营成本高。
- 对**当前公司(非美、跑 PM)**: 没美国实体 = Kalshi 接不进 = **此刻执行不通**, 除非建美国实体(大合规工程)。

### 约束 B — Alpha: 价差是否够大够持久 (待测, 是 GO/NO-GO 总开关)
- **可比性问题**: Kalshi BTC 是【区间桶】(price in bucket), PM 是【阈值】(above X) → 解析不同, 不能直接套。**干净套利需【解析完全相同的二元盘】**(同一场比赛胜负 / 同一选举 yes-no)。但 Kalshi 体育多是 multi-game 篮子(illiquid), PM 体育是 in-play —— 流动+解析都对齐的重叠盘**稀缺**。
- 预测市场套利**竞争充分**(很多人盯), 大而持久的价差先验不乐观。
- **必须实测**: 选解析相同的流动重叠盘(优先大选/macro 二元事件), 监控 Kalshi-vs-PM 价差时序, 看是否 > 双边 fee + 两实体运营成本。

## 可行性结论 (倾向)
- **机械上可套** (两实体锁差成立), 但**执行墙高**(司法冲突 → 双实体 → 当前公司接不进 Kalshi)。
- **Alpha 未验且先验不乐观**(可比流动重叠盘稀缺 + 套利竞争充分)。
- **GO/NO-GO 取决于实测价差**: 若某类解析相同的流动盘 Kalshi-PM 价差稳 > 成本 → 值得评估两实体; 若价差小/瞬时 → 不值这个复杂度。

## 下一步 (若继续)
建 spread-monitor: 匹配 Kalshi↔PM 解析相同的流动盘(先试大选/macro), 时序记录两边 bid/ask, 算价差分布 vs 成本。这是回答约束 B 的唯一办法, 数天数据。**但即便价差存在, 约束 A(司法/双实体)是产品+合规决策, 非工程能解。**
