## TL;DR — NO-GO (无可抓的、有流动性的、扣费后为正的 edge)

测了 5 条独立路径, **全部被堵**, 且**每一个"看起来有 edge"的信号, 深查后都化成了假象**(口径/波动率/陈旧价/书太宽)。根因与 in-play 体育**同源**: 没有一个"同时满足 ① 真实 ② 有流动性可进 ③ 穿过真实盘口后仍为正"的低效。

不同点: BTC 的**公允(现货)是实时零延迟的**(Deribit/Binance ms 级), 我们低延迟基建在这里是**资产**(体育是 Goalserve 2.3s 数据延迟把它废了)。但"基建合适" ≠ "有 edge 可赚" —— 有流动的地方都被定价对了。

## 关键方法学修正 (为什么"偏离"都是假的)

1. **到期错配 (v1 致命错)**: 拿"22分钟后结算的 Kalshi 盘"去比"21小时后到期的 Deribit"= 比的是不同时刻的 BTC, 假出 30-42c 巨幅"偏离"。修: 公允必须算在**盘自己的结算时刻**上。
2. **期限结构 (v2 修)**: 公允的 σ 要按期限结构在总方差上插值; 用最近到期 IV 套所有 horizon → 长周期盘假出 5-8c 偏离。修后 10h/82h 偏离塌到 ~0。
3. **亚小时 vol << 1日 IV**: 临近结算盘 Kalshi 报价的分布**更紧**, 不是错价 —— 实测最近15min 实现vol 31.6% vs 21h 期权IV 43%。期权IV含隔夜/事件风险, 高估了15分钟的vol。Kalshi 是对的, 我的公允用错了 vol。
4. **现货会动**: 单帧"偏离"里很大一块是现货从取样到比对之间漂移(spot 62645→62698, +$53 单独就把 P(>62500) 从0.80抬到0.91)。
5. **gamma 中价是陈旧 last-trade, 不是真盘口**: PM daily up/down 的"9c FLB"全错在拿 0.135 陈旧中价当真; 真 CLOB 书已把公允套在 0.89/0.99 里。**真盘口永远以 CLOB /book 为准, 不信 gamma outcomePrices。**

## 前向记录器实测 (20分钟, 3s步, 20472行, btc_log.csv)
- **滞后**: Δspot↔Δmid 互相关在 lag 0~4步(0~12s) 全 ≈0.00 → 无"Kalshi 滞后现货可抢跑"的信号(注: 自动选档落在OTM, 信号弱, 但无正向迹象)。
- **结算源**: PM 5-min 用 Chainlink data-stream(亚秒, 需付费API凭证, 非自由轮询); PM daily up/down 用 Binance BTC/USDT noon-ET; Kalshi 用自己的指数。**三家结算源都不同** → 跨家对冲必带基差。

## 唯一真实但抓不到的低效: 偏好-冷门偏差 (FLB)
- 冷门(低价腿)在**中价**上系统性偏贵(daily up/down: UP中价0.135 vs 公允0.043)。这是文献里持久存在的预测市场低效。
- **但抓不到**: 真 CLOB 书在冷门侧要么 bid 极低(0.10)要么对侧 ask 是墙(0.99), 穿过真实盘口后净 edge ≤ 半价差。耐心限价单偶有零售冷门买家来吃, 但 fill 率低 + 持有到结算的方差大 + PM crypto 费 0.072·p(1-p)。**是统计 edge 不是锁套, 且执行受限。**

## GO/NO-GO
- **NO-GO** 作为"快速 +200u"路径。BTC 预测市场: **有流动处=已定价对, 有理论edge处(5min/抢跑)=没流动或书太宽。**
- **会翻案的条件**(任一): ① 某 venue 同时有流动 + 近钱 + 真盘口可穿的偏离(需长期多日记录器盯, 不是一下午快照); ② 拿到 Chainlink data-stream 凭证且实测它显著滞后真现货(抢跑5min盘) + 那些盘有流动; ③ 把 FLB 做成跨多盘的耐心限价收割(慢、吃资金、靠零售流, 非BTC专属)。
- 这三条都不是"改代码重部署"能解的, 是**产品/数据接入/策略范式**层面的事。

## 网速 edge 实测 (2026-06-09, 伦敦服务器, 用户「我们有网速优势」)

> 笔记本测不准(1s/venue 延迟)。改在**伦敦部署节点**实测各 venue 真后端延迟 + 高频采样。

**真后端往返 (非CDN缓存):**
| venue | 伦敦服务器 RTT | 说明 |
|---|---|---|
| Deribit 现货 | **~28ms** | 快 |
| **Polymarket CLOB** | **~30ms** | **快 —— 这是我们真正的速度优势** |
| **Kalshi orderbook/下单** | **~110ms** | 撮合引擎在美国, 跨大西洋 |
| Coinbase | ~115ms | |
| Binance | ~234ms | 慢 |

**反应回路时间 (抢 stale 报价):** 读现货28ms + 读Kalshi 110ms + 下单110ms ≈ **~250ms** 到 Kalshi。美国 co-located 机器人 <10ms。**竞速里我们慢 ~240ms → 永远最后到。**

**结构性错配 (致命):**
- **我们快的 venue (PM 30ms): 没有又活又高gamma的crypto盘** —— PM crypto = daily up/down(低gamma, UP在0.09) 或 5-min(死, $6量)。
- **高gamma活盘所在的 venue (Kalshi 近结算): 离我们110ms(美国)**, 且 BTC 只 12:00/21:00 一天两次结算, 美国机器人秒杀。
- 服务器采样: 顺序REST ~4.7Hz(193ms/帧, 受110ms Kalshi腿拖累); 真ms级须WSS。Kalshi 9h外的盘根本没挂单(MM临近才报价)。

**B路实测 (PM是否滞后现货, 服务器6.6Hz×240s):** 扫遍PM crypto, 唯一有真双边书的盘全在 mid=0.99(深ITM, gamma≈0); 探针标的现货动$137 → PM mid 0次变化, 互相关全0.00。**不是"PM跟得上"而是"PM唯一有流动性的crypto盘gamma≈0钉死0.99, 没东西可套; 有gamma的(5-min)没书(死)。"** → **B路从伦敦也无标的可吃。**

**速度 edge 判定: 优势真实但地理错配 (A/B 两路实测全闭)。** 从伦敦吃不到 Kalshi(美国венue), 能吃到的 PM 没有高gamma活盘。要让速度变现需: ① 美国 co-location 贴 Kalshi(换基建+美国实体); 或 ② 在PM上**做市**5-min crypto(我们快+实时现货公允 → 杀死体育做市的"2.3s数据延迟逆选"在这里不存在, 但盘子现在没量, 需流量验证)。
