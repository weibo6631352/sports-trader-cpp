## 1. "不做全程跟盘, 只做关键节点窗" — 我认不认?

**结论: 半认半改, 一句话总结 — 关键节点窗的"硬不全程"我撤, "热度自适应"我加.**

理由三条, 全部基于本 Sprint 实测.

**(1) 小袁实测把我的延迟假设打脸了 (好的方向)**

我 v1 §3.7 拒"全程跟盘", 引用的是"跨洋延迟承担不起". 这个论据现在站不稳:
- 小袁实测 临场前 non-hot quote `T_{1/2} > 120s`, 临场 hot `T_{1/2} ≈ 0.21s`
- gameday $2K 吃单中位滑点 = 0¢ (best ask 一档吃完)
- 64 ms 跨洋 RTT (老姜可证) + 我们 ~500μs 本地热路径 = 跨洋链路本身**不是**"全程跟盘"的天花板

意味着: 我原来"全程"= 全场 7x24 跟单的工程负担想象, 在 non-hot 临场前其实是"60s 一帧"的低频任务, 不需要全程刷.

**(2) 小程信号目录已经把"关键节点窗"模糊化了**

小程的 P0-02 score-price-mismatch 触发条件是 `inplay && |z| ≥ 2σ && depth ≥ 30K`, 这本质上是**"事件触发"**而不是"节点窗". 我当初定的"Q1 末 / 半场 / 大比分跳变后 5min" 是节奏锚, 但执行层应是: **由 staleness/event/depth 三因子 OR 触发, 不是定时窗**.

**(3) 但 L2 半自动等级的人工节奏不能动**

D-06 (30s 数据缺失自动暂停) + 双人 ack 复位 (老韩 §4.3) 是 RM 红线, 这两条不退. 任何把"关键节点窗"扩到"持续监听全程" 的提议, 必须先把 RM watchdog 的 30s 阈值守住.

**收口表述 (写入 v1.1):**

> Inplay 信号触发条件改为 **"事件 OR 价格偏离 OR 流动性 OR 维持期阈值"** 四元 OR (不是定时节点). 但单笔持仓上限 30 min 强制 close (小梁 §8.1) 不动, RM watchdog 30s 阈值不动, 人工 arm/disarm 不动. 这不叫"全程跟盘", 叫"事件驱动的连续监听". 拒绝清单 §3.7 重写为正面定义: **"信号 + 风控触发的连续监听 + 30 min 持仓上限 + 节点窗外不发起新 intent"**.

## 2. MVP 锁 Moneyline + 0 套利 / 3% taker 硬底线 — 影响 alpha 吗?

**结论: 不影响 alpha 起点, 但影响 alpha 容量上限的我之前没说够.**

小袁实测三个数字直接重写我对 alpha 的脑图:

| 实测 | 我 v1 假设 | 调整 |
|---|---|---|
| cross-side equiv vig 中位 0.1-2.5¢ (NFL/MLB 最锐) | "等效 vig 2-4%" (小梁 §3.3) | 比我以为的更窄, edge 阈值更低也能正期望 |
| 0 个 arb hit (bid_yes + bid_no > 1) | 没估过 | 套利机器人勤奋, **跨边瞬时无风险套利已不存在** |
| taker 3% / maker 0% + 0.25 rebate | 不知 | **taker 3% 是硬底线, 我们策略 expected edge 必须 > 3% 才正期望** |

**对 MVP alpha 的影响**:

- **正面**: 1¢ spread + 0.1¢ vig (NFL/MLB) 意味着 1 套信号只要打到 1.5-2¢ edge 就能正期望. P0-01 (Pinnacle no-vig revert) 小程预期 edge 2-3¢, P0-02 比分失配 1.5-2¢, **数学上有空间**.
- **负面**: 3% taker 费意味着 P0-02 (score-price-mismatch) 预期 edge 1.5-2¢ 在 $0.50 价位 ≈ 3-4% notional, **净 edge 接近 0**. 这条信号实际是 borderline, 不能盲目当 P0.
- **结构性**: 0 套利意味着我们不是"捡漏", 我们是"撞 maker 库存的 lag". 这就要求 P0-01 的 Pinnacle 数据稳定性 + P0-02 的比分模型质量, **数据问题 = alpha 直接死**.

**收口决议**:

1. **MVP 锁 Moneyline 不变** (D-01). 小梁 §6 五点论证 + 小袁实测 gameday $2K 中位滑点 0¢, 起点足够稳.
2. **P0-02 暂从"首发并列"降到"必须有净 edge 证明才上线"**. 给小程 + 小梁的 hard gate: M2 (T+10 周) 前 P0-02 必须给出**含 3% taker 费的 OOS Sharpe**, < 0.8 则只 P0-01 单信号 MVP. (拒绝清单 §3.3 维持"1 套信号" — 1 套可以是合议, 不一定要 2 个独立信号上线.)
3. **alpha 容量上限我之前没明说, 现在补**: 小梁 §7.4 推断 $5-20M 全平台容量, 我接受. 老雷在 Sprint-2 规划要听到这个数, **不要规划 $100M AUM 路径**.

## 3. M4.5 7 gate 严格度 — 我接受吗?

**结论: 全部接受, 一个字不松.**

7 个 gate 我逐条比对我 v1 拒绝清单 + OKR KR-C, 没有冲突, 而且**比我 v1 给的"实盘首笔 + 72h"更严**, 这正是我要的方向.

| Gate | 我的态度 | 关联我 v1 |
|---|---|---|
| G1 PnL > 0 + t-test p<0.10 | 接 | §6.1 北极星 |
| G2 Sharpe > 1.0 + bootstrap CI 下界 > 0.3 | 接, 这条小董严格化我支持 | §6.1 KR-C-4 |
| G3 风控失效 = 0 | 接, 红线 | §2 + D-02 |
| G4 Uptime ≥ 99.5% | 接 | KR-C-2 起点 |
| G5 max DD ≤ 8% | 接, 这条比我之前没明给的强 | 小梁 §3.6 暗含 |
| G6 n_trades ≥ 50 防 cherry-pick | 接, 这条小董做对了 | KR-C-4 量化 |
| G7 shadow > random-entry baseline, paired p<0.10 | 接, 防 lucky bias | §3.3 暗含 |

**我自己的额外加码 (写入 v1.1 拒绝清单)**:

- M4.5 失败 1 次 → 留 paper 多 2 周; **失败 3 次 → 走我 v1 §5.2 战略级升级路径**, 老雷 + 我 + 小梁 三方战略复盘是否撤回 MVP scope (这条 OKR M4.5 段已经写, 我背书).
- M4.5 通过后实盘上量, **W1-W3 节奏 (OQ-D12) 我接, 但额外锁: W1 单笔 $200 不是"建议", 是 hard cap, 写入 RM 软参数**. 任何 PR 改这个值走我 §5.2 中级升级路径 (老钱 + 老雷双签).

**我对 7 gate 唯一的担忧**:

G2 bootstrap CI 下界 > 0.3 + G6 n_trades ≥ 50, 数学上要求 14 天内 ≥ 50 笔 + Sharpe > 1.0 + CI 下界 > 0.3 — 这是**很高的统计功效**. 小董在 OKR 段已经标了"样本量警告 14 天功效不足", 我加: **如果 M4 期间发现 14 天打不出 50 笔, 信号触发频率不达标本身就是问题**, 不要靠"扩到 30 天"凑数据, 而要回头看小程信号 trades/月 估算 (P0-01 NBA+NFL 合计 20-60, 已经吃力).

## 4. 小杜 PRD v1 我认不认?

**结论: 主体认, 4 处要求 v1.1 改.**

小杜的 PRD 是我看过最纪律的 PRD: 全篇引用我 / 老韩 / 老周 / 小梁, 没有重写 scope, 没有"我顺便加 X". 这是合格的 PM 工作. 主体我会签.

但有 4 处, 等小杜 v1.1 改完我才会签:

**(1) §4.1 F-19 Replay 框架列 P0** — 与我 v1 §3.4 "❌ 回测 replay UI" 重叠但**不矛盾** (我拒的是 UI, 不是 framework). 小杜要在 F-19 描述里明写 **"CLI only, 不做 UI"**, 避免 sprint-3 有人借 F-19 上 Web. 这是 §5.1 第 8 条 "顺便即 creep" 的预防.

**(2) §5 F-05 信号 v1 写"5.1 + 5.2 + 5.3 三组件复合判断, 不算 3 个独立信号, 算 1 套合议"** — 这条我**坚决拒绝**这种描述. 我 v1 §3.3 "信号数量 = 1" 是 hard cap, 不是 "≥1". "三组件合议" 是 ensemble 的雅称, 我不接受语言游戏.

收口写法: 
> P0-01 (Pinnacle no-vig revert) 是 MVP 唯一启用信号. P0-02 在 M2 OOS Sharpe ≥ 0.8 (含 3% taker 费) 通过前不上线. P1-03 Goalserve 时延信号 M4 前不进生产. 维持 "1 套信号" 字面定义.

**(3) §7.1 性能表里 "信号 + 定价 80μs"** — 这是老周 §11 的数字, 但我作为 CPO 要说一句: **80μs 是工程目标, 不是产品验收**. 验收口径仍然是 KR-A-3 "热路径 p99 < 500μs (信号→下单指令)" 整段, 不要把单段 80μs 当门禁. 小杜 v1.1 把这表标 "工程内部目标, 不是产品验收".

**(4) §8.4 影子模式签字 "老韩 + 老雷 + 小梁 + 老钱 四方双签"** — 我接, 但补一条: **影子模式至少跨越 1 个完整 NBA + 1 个 NFL 周末**. 不能只跑 MLB 工作日 (流动性 + 信号触发分布不代表). 这是 §8.4 验收口径的精度补充.
