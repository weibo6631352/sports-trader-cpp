## 0. 序 (为什么有这份文档)

sports-trader-cpp 是私人量化项目, 但在 Polymarket (CFTC 灰区) 上跑钱 + 跨洋链路 + 用第三方数据 (Goalserve) — 任意一个环节踩红线, 后果不是罚款而是 **账号清零 + 资金冻结 + 民事/刑事风险**. 这份文档不是法律意见 (我不是律师), 是项目内部的工程红线. 全员签收, 出事按文档追责.

## 2. 司法管辖区 (我们在哪运营)

### 2.1 项目主体定位
- Operator: 自然人, 中国大陆居民
- 服务器/部署地: 跨洋链路 (北美/欧洲 VPS, 具体见 infra)
- 资金路径: 链上 USDC (Polygon) ↔ Polymarket 合约

### 2.2 高风险司法管辖区清单

| 地区 | 风险等级 | 红线 |
|------|---------|------|
| **美国** | EXTREME | Polymarket 2022 CFTC settlement 已禁美国用户; **绝对不得**用美国 IP / 美国身份 KYC / 美国银行卡入金 |
| **中国大陆** | HIGH | 加密资产 + 境外博彩双重灰色; 不公开宣传, 不接受境内用户拉新, 资金不走境内银行 |
| **欧盟 (DE/FR/IT)** | MEDIUM | MiCA + 本地博彩牌照敏感; 不主动面向欧盟居民提供服务 |
| **英国** | HIGH | GC (Gambling Commission) 严格, Polymarket 在英国已被屏蔽 |
| **新加坡 / 香港** | MEDIUM | 灰区, 个人交易低风险但不可公司化运营 |
| **OFAC 制裁名单国** | EXTREME | 伊朗/朝鲜/古巴/俄罗斯部分地区/叙利亚 — **绝对禁止**任何关联 |

### 2.3 IP / VPN 红线
- 部署服务器 **不得**位于美国 / 英国 / OFAC 国
- 个人访问 **不得**直接从受限地区 IP 触达 Polymarket UI
- VPN 出口节点必须稳定且非受限地区

## 3. Polymarket ToS 关键条款 (摘要)

> 完整条款实时为准, 此处摘 2026 Q1 版本要点. ToS 技术细节 (rate limit / endpoint 行为) 个案咨询 @老李.

### 3.1 资格 (Eligibility)
- 用户必须 18+
- 用户 **不得**为 Restricted Person (美国人 / 受制裁人士 / Polymarket 员工)
- 一人一账户, **禁止多账户** (后果: 全部余额没收)

### 3.2 API / 速率限制
- CLOB API: 公开 endpoint 软限 ~10 req/s, 鉴权 endpoint ~50 req/s (具体看 @老李 探测结果)
- WSS: 连接数 & 订阅数有上限, 滥用导致全 IP 封禁
- **禁止**: 绕过限频 (多 IP 轮询同账户), 抓取超额数据转卖

### 3.3 反操纵 (Market Manipulation)
Polymarket ToS 明确禁止 (措辞接近 CFTC Rule 180.1):
- **Wash Trading**: 自买自卖
- **Spoofing**: 挂大单不打算成交, 诱导对手方
- **Layering**: 多层假单制造深度假象
- **Marking the Close**: 收盘前刻意操纵结算价
- **Insider Info**: 用未公开的赛事信息 (例如收买球员/裁判) 下单

### 3.4 资金 / 提现
- 入金: 仅接受 USDC (Polygon), 不接受信用卡/电汇
- 提现: 走链上, 大额可能触发额外审核
- 账户冻结条件: 多账户 / 制裁名单 / 反操纵证据 / KYC 失败

### 3.5 数据使用
- 行情数据可用于个人交易决策
- **禁止**: 转售 / 公开二次分发 / 训练对外商业模型

## 4. 绝对禁止清单 (一票否决)

**任意一条触发, 老黄有权直接叫停代码合并 + 关停相关功能, 不需要二次确认.**

| # | 红线 | 说明 |
|---|------|------|
| R1 | **多账户操作** | 我们只有一个 Polymarket 账户. 任何代码逻辑暗示"切换账户"都禁止 |
| R2 | **Wash Trading 自买自卖** | 同账户两侧挂单互吃, **绝对**禁止. 即使是"对冲测试"也走 testnet |
| R3 | **Spoofing / Layering** | 挂单必须有真实成交意图. 撤单率监控触发阈值要 alert |
| R4 | **美国 IP / 美国 KYC** | 任何环节带美国元素全部 block |
| R5 | **OFAC 制裁名单关联** | 钱包 / 对手方 / 数据源任意一环命中, 立即停 |
| R6 | **未公开信息交易** | 不得购买/接收未公开赛事信息 (内幕/作弊源) |
| R7 | **绕过速率限制** | 多 IP 轮询同账户 / 伪造 header / 复用 token 滥用 |
| R8 | **私钥明文落盘** | 私钥不进 git, 不进日志, 不进 Slack/邮件. 详见 @老叶 链上规范 |
| R9 | **数据转售** | Polymarket / Goalserve 数据不得对外转售或二次分发 |
| R10 | **公开宣传/拉新** | 不发推/不开 Discord/不做策略服务. 个人项目身份 |
| R11 | **跨链桥未审计资产** | 资金路径只走 USDC.e (Polygon) 主路径, 不碰野桥 |
| R12 | **AI agent 自主提币** | 提币 = 人工确认 + 多签 (如果 setup), agent 不得拥有提币权限 |

## 5. 灰区清单 (个案 review)

**这些不是绝对禁止, 但每次实施前提交 1-page proposal 给老黄 review, 留档.**

| # | 灰区 | 个案考量 |
|---|------|---------|
| G1 | **多策略并行下单** | 同账户跑 ML/Spread/Totals 多策略, 可能被识别为 wash. 需要订单去重 + 反向单冷却期 |
| G2 | **Maker rebate 挖矿** | 高频挂撤如果只为刷量被视作 spoofing. 必须有真实成交配对 |
| G3 | **Outright / Series 长持仓** | 持有数月仓位, 在赛事最后阶段可能涉及"内幕"边界, 注意信息源合规 |
| G4 | **Prop 市场低流动性套利** | 容易被定性为"操纵小盘". 单笔规模硬上限 |
| G5 | **跨场馆套利 (Polymarket vs 其他预测市场)** | 法律地位差异, 个案看对手方合规性 |
| G6 | **AI agent 决策权下放** | agent 自动下单 OK, 自动调高仓位上限 / 自动改风控参数 NO. 边界要写死 |
| G7 | **回测数据来源** | 历史快照如果来自爬虫第三方可能违 ToS, 优先用官方 archived endpoint |
| G8 | **数据缓存到本地** | 个人使用 OK, 缓存超过 7 天 + 二次分发 = R9 |

## 6. KYC / AML 要求

### 6.1 Polymarket KYC 现状 (2026)
- 大部分体育市场仍可无 KYC 交易 (链上托管模式)
- 大额提现 / 法币出入金 (如开通) 触发 KYC
- 一旦触发 KYC: 提交身份信息 **必须真实**, 不得用美国身份 (R4)

### 6.2 AML 自检 (我们的钱来源)
- 入金 USDC 来源必须可追溯到合规交易所 (Binance/OKX/Coinbase 等)
- **禁止**: 接收来源不明的 USDC (mixer / tornado / 黑 U)
- 链上地址定期扫 OFAC + Chainalysis 风险评分 — 详细方法 @老叶

### 6.3 我们这边的 KYC 触发场景
- 单笔提现 > $10k USDC
- 累计提现 > $50k / 月
- Polymarket 主动要求 (账户被风控)

触发后流程: 暂停所有自动化 → 老黄 + 老雷决策 → 人工应对

## 7. 数据使用合规

### 7.1 Polymarket 数据
- gamma / clob / data REST + WSS: 个人交易使用 OK
- **不得**: 提供数据 API 服务 / 转卖给第三方 / 公开 dashboard 含实时报价
- 抓取频率不超过 ToS 速率限制 (见 §3.2)

### 7.2 Goalserve 数据
- 按订阅条款使用 (inplay / livescore / pregame)
- token 不得公开分享, 不得多账户共用 token
- 数据缓存仅供本系统决策, 不对外提供
- 退订后立即清除缓存

### 7.3 用户数据 (我们不收集用户数据)
- 项目无外部用户, 不涉及 GDPR / PIPL 主体责任
- 但: contributors 个人信息 (邮箱/钱包地址) 仅项目内部使用, 不对外披露

### 7.4 日志 / 监控数据
- 日志可包含交易记录 + 行情快照
- **不得**包含: 私钥 / API secret / KYC 资料
- 日志保留 90 天, 加密存储, 详细规范 @安全官

## 8. 监管动向 (持续追踪)

### 8.1 美国 CFTC
- 2022: Polymarket settlement $1.4M, 禁美国用户
- 2024: Kalshi 选举市场判决放松了部分预测市场限制
- 2025-2026: CFTC 对体育预测市场态度仍模糊, **趋势是收紧 prop bet 边界**
- 影响: 我们继续避开美国, 但要注意 Polymarket 自身合规变化可能传导到 ToS 收紧

### 8.2 美国 SEC
- 关注重点是"代币是否证券", 与体育预测市场关系小
- 但若 Polymarket 发币, 我们持有需评估

### 8.3 欧盟 MiCA
- 2024 全面生效, 加密资产服务商 (CASP) 牌照要求
- Polymarket 未在欧盟拿牌, 已主动屏蔽部分国家
- 影响: 部署节点避开欧盟核心国

### 8.4 中国大陆
- 加密 + 博彩双红线无松动迹象
- 个人海外交易未明确入刑, 但灰色
- 影响: 资金不回流境内, 不在境内宣传

### 8.5 监管 alert 机制
老黄订阅: CFTC press release / Polymarket blog / Coin Center / 链上合规通讯
重大监管事件 24h 内出 brief, 触发条款 hotfix.

## 9. 违规升级路径

### 9.1 发现违规 → 报告
任何 contributor 发现潜在违规 (代码 / 操作 / 数据):
1. 立即在 Slack #compliance 私聊老黄
2. 24h 内书面说明 (邮件 / issue)
3. **不要**自己悄悄 fix 后假装无事 — 留档比 hide 重要

### 9.2 老黄处置权
- **L1 (灰区)**: 老黄 review, 出 memo, 决定继续/调整
- **L2 (红线触发)**: 老黄一票否决, 立即停代码 / 停功能, 升 CPO (老雷代行)
- **L3 (已造成实际违规)**: 老黄 + 老雷 + 必要时外部律师, 主动应对监管/平台

### 9.3 CPO 升级
本项目 CPO 角色由老雷代行 (GM). 老黄判定 L2+ 必须升 CPO, 不得自行隐瞒.

### 9.4 紧急叫停权 (Kill Switch)
老黄有权在以下情况单方面叫停生产系统:
- 收到 Polymarket / 监管机构正式 notice
- 发现 R1-R12 任意一条正在被触发
- OFAC 名单更新且我们有地址命中

叫停后 24h 内召集老雷复盘, 但叫停动作本身不需要事前批准.
