# 评审会纪要 — HTTP/2 上后端可行性

**owner:** 老雷 (GM)
**last_review:** 2026-06-02
**召集人:** 老板 (要求评估 HTTP/2,核心顾虑:① 对服务器负载大不大 ② 会不会影响交易业务)
**参与:** 老王 (网络) / 性能 / SRE / 老韩 (风控) / 老郭 (架构评审)
**结论:** **推迟,现阶段不上**(5 位一致)。若将来要上,限定走【前置反向代理】方案,不动 paper_server。

---

## 背景

看板后端 API = `src/stcpp/debug_api/`(cpp-httplib v0.16.3,**HTTP/1.1 明文**,端口 8080),是【只读观测】服务,跨洋服务国内操盘手(伦敦 EC2,RTT ~200ms)。

动机:浏览器对单 origin HTTP/1.1 仅 6 条 TCP 连接,HTTP/2 多路复用可破此限。
**但** 已完成的优化已绕过该瓶颈:
- 前端全局并发闸(cap 6,镜像浏览器上限);
- 批量端点 `GET /api/v1/grid`(一次返回全部 ~350 市场摘要,每轮请求 350→1~5);
- 用户交互优先级插队。
- 稳态:0 超时,p50 ~440ms(**200ms RTT 主导,非连接数主导**)。

---

## 五方评审结论

| 视角 | 结论 | 关键论据 |
|---|---|---|
| **网络 (老王)** | 推迟 | cpp-httplib 不支持 h2(只 HTTP/1.1)。上 h2 要么换库(nghttp2,1-2周,重写 20+ 端点,中风险)要么前置反代(httplib 零改动)。**/grid 批量化后 h2 多路复用净收益 < 5ms**,RTT 200ms 是物理墙。 |
| **性能** | 推迟 | 负载**不是问题**:TLS 在此流量(几请求/2s,50KB)CPU < 0.1%;nginx 反代 < 0.5% CPU。机器 56% CPU / idle 60% / load<1,距 4vCPU 饱和 5 倍余量,**不抢交易核**。但延迟改善 ≈0ms(RTT 主导)。 |
| **SRE** | 推迟 | 无域名只有公网 IP → Let's Encrypt 签不了 IP,得买域名或自签(浏览器告警)。反代破坏"kill 即停"运维模型,需 systemd 例外 + 新故障面(代理挂/证书过期→看板全黑)。对纯观测面不划算。附带收益:TLS 顺带加密观测数据(威胁等级低)。 |
| **风控 (老韩)** | 批准但限方案 | 已核实隔离:HttpServer 持 `const StateProvider*`,只读,独立线程,**与 PaperLoop/CLOB WSS/RM/signer 物理无交集,不触任何 §8 红线(含 R-12)**。CLOB WSS 是 outbound 连 Polymarket,与本机 HTTP 协议无关。**反代方案业务风险面归零;换库方案(动交易进程)不批。** |
| **架构 (老郭)** | 推迟/不上 | 高延迟链路瓶颈是 RTT×往返次数,不是并发度。/grid 已把瓶颈从"连接数"治回"RTT",**h2 是治一个不再发作的病**。更对的下一步是 **SSE 推增量**(减往返,过 H1、无需 TLS,httplib 原生 chunked 可做),而非 h2(加并发)。 |

---

## 老板两个顾虑的直接回答

1. **对电脑负载大不大?** —— **不大**。TLS 在看板这点流量下 CPU < 0.1%;反代进程 < 0.5% CPU。机器还有 60% idle、5 倍余量,**不会挤占交易/训练/采集的 CPU**。负载不是阻力点。
2. **会不会影响业务?** —— **走反代方案:零影响**。观测 API 是只读、独立线程、与交易热路径(决策/下单/签名/WSS)完全隔离,改它对交易字节级不动。**换库方案(把 h2 状态机塞进交易进程)有风险,老韩不批。**

**真正的否决理由不是风险,是收益≈0:** 瓶颈是 200ms 跨洋 RTT(物理限制),/grid 已绕过 6 连接限制,h2 在此链路边际收益 < 5ms,而成本(TLS 证书/域名/反代/新故障面/运维例外)不成比例。

---

## 决议

- **现阶段不上 HTTP/2。** 继续走"减少往返次数"路线(批量化已见效)。
- **重新评估的触发条件**(任一):
  1. `queuedCount()` 长期 > 0(并发真打满 6 槽,瓶颈回到连接数);
  2. 请求种类暴涨、无法再批量化;
  3. 多操盘手共享同一 origin,连接数线性放大;
  4. 因别的原因(安全合规)已上 TLS+反代 → h2 边际成本趋零时顺带开。
- **若届时要上:限定方案 = 前置 nginx/Caddy 反代(h2+TLS 终结,回源 HTTP/1.1),paper_server 进程内零改动。** 换 C++ h2 库的方案不批(风控否决)。
- **更优的下一步备选(性价比高于 h2):** 把看板从 5s 轮询改为 **SSE 服务端推增量**(往返次数→0,无需 TLS,cpp-httplib 原生支持),以及把 detail/score 也纳入批量。需要时单独立项。
