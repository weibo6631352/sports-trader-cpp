# ADR-015: vCPU pin 策略 — C 阶段性 (paper 现状 + WAL bg 4 线程, M5+ 前升 7 vCPU)

- **ID:** ADR-015
- **Date:** 2026-06-01 (W5 末)
- **Status:** Accepted (GM 老雷拍板, Wave 27 投票)
- **投票**: C 4 (老周/老韩/小梁/老郭) / A 1 (小余) / B 1 (老胡)

## 决议

- paper 阶段 (W6 ~ M5+ live 前): **main thread (decision) + 4 WAL bg fsync 线程** (老王 v0.2 现状, 实际是 5 thread)
- 不强 pin 7 vCPU (paper p99 3.9us 余 200x+, 跨洋 RTT 200ms 是绝对瓶颈)
- M5+ live 前: **老姜真实压测 (S2-011 6/22) 后升 7 vCPU pin**

## 实施

- W6: 维持现状 (main + 4 WAL bg), 不动
- W6 起: 老姜 latency bench 上下界 + Smell 老胡 #1 conditional B "等 6/22 压测数据"
- M5+ 前: 老姜 7 vCPU pin spec + 老周 v0.7 §8 启动期 11 步 (含 pin step)

## 反对方理由 (申辩记录)

- 小余 A: "老王 WAL v0.2 core 6/7 已分配 4 个 bg fsync 线程, 压缩 2-3 会让 WAL bg 与 ETL ingest 抢 core"
- 老胡 B: "先等 S2-011 压测 6/22 数据, 不达标走 MVP NBA only 降级路径"

GM 答复:
- 小余 A 关键论据 **已部分采纳** — paper 现状不是严格 single thread, 实际 main + 4 WAL bg = 5 thread
- 老胡 B "等 6/22 压测" — 与 C "M5+ 前老姜 bench" 一致
- 真实工程: paper 现状 (5 thread) ≠ 严格 single thread, 也 ≠ 强 pin 7 vCPU, C 阶段性最合理
