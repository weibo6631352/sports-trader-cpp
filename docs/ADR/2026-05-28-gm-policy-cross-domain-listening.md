## 1. 用户原话

> "架构和数据结构 网络等任何与问题相关人员必须认真听取"

## 2. 政策

会议 / 评审 / ADR / PR review 时，**跨域相关人员有"听取义务"，不是可选**。

**听取义务三件套：**
1. **必到** — 议题相关人员不到 = 会议不立
2. **听完才发言** — 不允许只关心自己模块，发言前必须复述对方观点要点（"我理解你的意思是 X，对吗？"）
3. **反馈入纪要** — 每个被点名的相关人员必须在会议纪要里有发言记录，含赞同 / 反对 / 补充

## 2.5. 双向回应 + 合意收口（用户 2026-05-28 第二条强化）

> **"每次交流必须有回应，达成合理意见。"** — 用户原话

**交流不允许单向**：
- 任何"我说我的，你说你的"无收口的讨论 → 协作失败，主持人责任
- 每条议题必须走到下列三态之一才能 close：
  - ✅ **Agreed** — 双方/多方明确接受
  - ⚖️ **Compromised** — 双方让步达成可接受方案
  - ⬆️ **Escalated** — 双方无法对齐，明确升级 GM / owner 拍板
- **禁止"先这样吧，回头再说"** — 没有截止日的延期 = 没决议
- **禁止"我先做我的"绕开冲突** — 会议未收口前，争议模块代码不准 merge

**会议主持人责任：**
- 每节讨论结束前点名："X 议题 — Agreed / Compromised / Escalated？" 不允许跳过
- 三态结论必须入纪要 + 带 owner + 带截止日
- 一周内未走到 Agreed / Compromised / 给 GM 升级 → 主持人扣 KPI（协作维度）

**PR review / ADR 同理：**
- Reviewer 写 "LGTM" 不够，必须明示对争议点的态度
- ADR 必须含 "听取确认清单 + 各方最终态度"

## 4. 听取义务违例 = 协作红线

- 议题决议跨域人员**未被征询** → 决议不立，重开会
- 议题相关人员**回应"我没看过那份文档"** → 立刻读完再发言，不允许凭直觉表态
- 议题相关人员**自己 owner 文档与他人冲突而不知** → 老胡周报点名
