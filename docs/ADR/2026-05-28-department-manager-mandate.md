# ADR: 部门主管 mandate — 统筹优先, 不亲力亲为

- **ID:** ADR-005
- **Date:** 2026-05-28
- **Owner:** 老雷 (GM) 拍板
- **Status:** Accepted
- **触发:** 用户原话 (2026-05-28 verbatim): "各部门应该评一个主管, 理论上主管尽可能的统筹部门的人员, 而不是事事亲力亲为。"
- **关联:** GM 错 #8 (越级派单, 架空主管) — INCIDENTS log

---

## 1. 背景

W3-W4 GM 老雷直接给单元内 IC 派单 (例: 跳过老周直接派老李 / 小段 / 小蒋 / 小颜; 跳过小梁直接派小程 / 小蒋 / 小袁 / 小肖 / 小董 / 小邓; 跳过老胡直接派小苏 / 小尤 / 小宋 / 小杜 / 小颖). 5 个战斗单元 Owner 实际上**只挂名不统筹**.

这违反"组织规模化"原则: GM 1 人协调 50+ persona 不可持续, 主管必须分担.

## 2. 决策

5 战斗单元 Owner 同时是**主管** (Department Manager). 顾问团另加协调人.

### 2.1 主管名单

| 单元 | 主管 | 工号 | Persona file | 兼任 |
|---|---|---|---|---|
| A 系统工程部 | 老周 | E-001 | `01-cpp-chief-architect.md` | 架构主权 |
| B 风控合规部 | 老韩 | E-009 | `09-risk-engineer.md` | RM 主权 |
| C 量化研究部 | 小梁 | E-018 | `18-financial-expert.md` | Sharpe/VaR/Kelly |
| D 数据基础设施部 | 小余 | E-022 | `22-data-etl.md` | ETL 主权 |
| E 产品业务保障部 | 老胡 | E-026 | `26-pm-project-manager.md` | PM milestone |
| F 顾问团 | 老郭 (协调人) | E-016 | `16-chief-architecture-reviewer.md` | 架构一票否决 |

注: 老钱 (CPO) 平级老雷, 不进主管体系, 但参与决策.

### 2.2 主管职责 6 条

1. **接 GM 目标拆任务:** GM 下达"业务目标 + 截止 + 约束", 主管自己拆成具体任务派给单元内 IC. GM **不**指定"谁做什么".
2. **单元内排队 + 优先级:** 单元 backlog 你定, 跨单元依赖由你与其他主管协商.
3. **review + 质量门禁:** 单元内成员产出, 主管 first review, 通过后 owner 收口或 push 老高/老郭/老雷.
4. **跨单元接口对接:** 与其他主管协商 (协商不下走 §6 决策机制升级老雷).
5. **KPI + 1:1 + 培养:** 单元内成员 weekly 1:1, 月度 KPI 评估, 跟 HR 小林联动.
6. **不亲力亲为:** 主管**不写代码** (例外: 架构原型 / 紧急 hotfix < 2h). 主管出 spec / 评审 / 决议 / 派单, **不**做 IC 工作.

### 2.3 不属于主管职责

- 主管不替老雷拍战略 (战略归 GM + CPO)
- 主管不一票否决其他单元产出 (除非该单元产出触动本单元红线, 这种情况升老雷 / 老郭)
- 主管不写代码 (除架构原型 / 紧急 hotfix)
- 主管不替 IC 单方面承诺其他 IC 工作量 (跨 IC 排队主管自己单元内可, 跨主管协商)

## 3. 新派单流程

### 3.1 GM → 主管 → IC (3 层)

```
GM 老雷 (业务目标 + 截止 + 约束)
    ↓
主管 (拆任务 + 排队 + 选 IC + 设质量门禁)
    ↓
IC (具体技术任务)
    ↓
主管 first review → 跨单元 review (老高/老郭) → GM ack
```

### 3.2 例外: GM 可直接派的场景

- **顾问团成员** (顾问本身是 GM 直属, 走老郭协调即可)
- **紧急 P0** (RM HALTED / 安全事件 / 用户原话指令 < 2h 响应)
- **主管自己** (GM 给主管派, 不算越级)
- **跨多单元统筹** (老胡 PM 周报 / 老郭 架构评审 / 老高 PR review v1.1) — 这些本身就是跨单元

### 3.3 GM 错 #8 教训永久 enforcement

GM 派 wave 前 **5 题自检** (原 4 题升 5 题):

1. 一面之词背书?
2. 单 agent 替全员说话?
3. 让 agent 看老项目 / 撤销方案?
4. 派单 prompt 越 persona "拒绝任务" 边界?
5. **是否越主管直接派 IC?** (5 战斗单元任务必经主管, 顾问团 / 紧急 P0 / 主管本人 / 跨单元统筹 例外)

CLAUDE.md §7-8 同步.

## 4. 主管间协作

### 4.1 跨单元接口对接

主管间协商 (24h ack, 48h 不下升老雷). 例:
- 老周 (A) 与 老韩 (B): RM C++ 接 audit emitter 接口
- 小梁 (C) 与 小余 (D): signal 数据消费 schema
- 老胡 (E) 与 全主管: Sprint 节奏 + 周报

### 4.2 主管月度同步

CLAUDE.md §5 会议节奏已有"Owner 周同步" (每周一上午, 老雷主持, 5 个 owner + 老钱, 45min). 改名 "**主管周同步**", 议程加:
- 各主管本周派单清单 + 完成率
- 跨单元 blocker
- 单元内 IC 健康度 (1:1 摘要)
- HR 招聘进展 (小林 dial-in)

### 4.3 主管轮值 GM 助理

每月 1 主管 dial-in 老雷, 学习 GM 视角 / 培养接班. 第 1 轮: 老周 (6 月) → 老韩 (7 月) → 小梁 (8 月) → 小余 (9 月) → 老胡 (10 月).

## 5. 主管就职宣言 (W4 末必交)

5 主管 + 1 协调人 各写 `docs/RESEARCH/<persona>-manager-mandate-v1.md` (≤ 300 行) 含:

- **§1 单元成员清单 + 工号 (registry 对齐)**
- **§2 我作为主管要做的 vs 不做的** (8 项 do + 5 项 don't)
- **§3 单元内 IC 当前工作量评估 (0-10)** (与 HR 小林 pulse 联动)
- **§4 单元 W5 派单 backlog v1** (主管自己拆, 不让 GM 拆)
- **§5 跨单元接口需求** (谁要协商, 24h ack 期望)
- **§6 主管 KPI 自评** (基于 v2 主管职责 6 条)

W4 EOW (2026-06-06) deadline.

## 6. 不变量

- 主管不 supersede Owner 技术权威 (主管 = Owner + 统筹, 两个 hat)
- 主管不替老雷拍战略
- 主管不写代码 (例外见 §2.2)
- 主管接 GM 派单 24h 内 ack, 48h 内拆出 IC 任务

## 7. 风险

- **R-41 主管装睡:** 接 GM 派单后实际不拆给 IC, 自己默默做. → 老胡周报追踪"主管派单覆盖率".
- **R-42 IC 等主管:** 主管不在线 / 拆任务慢, IC blocker. → 24h ack 硬约束, 超时升老雷.
- **R-43 主管 vs IC 越权:** IC 越过主管直接找 GM. → CLAUDE.md §7 行为铁律: 走主管不绕过 (GM 拒接绕过派单).
