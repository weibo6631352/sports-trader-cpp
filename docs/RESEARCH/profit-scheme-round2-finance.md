## 0. 结论先行 (TL;DR, 数字说话)

1. **我 round-1 "排除做市"的逻辑链条没被推翻, 但结论要分层修正。** 我当时排除做市的真因不是"maker 收费", 是**逆向选择**(§1-(b)第1条: "我们的论点是市场有 informed 时滞 → 做市要求信息不劣于对手流 → 自相矛盾")。激励池改变的是**收益侧**, 逆选损失侧**一分钱没动**。所以正确问题不是"做市能不能做", 是**"补贴 − 逆选 净不净正"**, 这是纯数字题, 不是定性题。

2. **算出来的数字: 我们这种 size 在 pro-rata 池里净期望大概率为负或贴地正, 但有一个例外区间是结构性正的。** 关键分水岭是**逆选损失** vs **激励份额**:
   - 逆选损失 (跨洋 200ms±50 RTT + 10s 心跳, 撤单跑不赢 bet365 跳动): 被扫一次约亏 **半 spread + move 幅度** ≈ 单边 notional 的 **1.5%–3%**, 进球类事件频率下**每场每边期望 2–4 次被扫**.
   - 激励份额: $5M/月 ÷ 全市场 pro-rata, 我们 MVP size ($1k–10k 量级) 在大鲸鱼 (做市商 notional $100k–1M+) 下**份额被稀释到 0.1%–2%**, 折算**单场单边日激励 $0.5–$15** 量级 (粗算见 §1.4).
   - **→ 在流动性厚 + 价格稳的市场 (无 informed flow), 净正; 在我们真正有信息优势的进球类 in-play 时刻, 净负 (被自己的信息优势反噬)。** 这是核心 paradox.

3. **主次必须倒过来。草案把激励做市当"广覆盖主引擎", 套利当"深叠加" —— 金融上错。** 真 alpha 是**信息时滞收敛套利**(承担 informed 角色, 我们站在快的一方); 激励做市是**补贴/降本层**(承担 uninformed 流动性角色, 我们站在慢的一方挨打)。**同一个团队的同一信息优势, 在两个引擎里方向相反。** 把补贴当主引擎 = 用我们最贵的资产 (信息速度) 去补贴别人。**套利是主, 做市激励是套利出场腿的副产品 + 价格平静期的低风险 carry, 不是独立广覆盖主引擎。**

4. **草案 P1 "先上无模型规则化做市" 会被逆选吃爆, 反对单独上。** 无避险大脑 + 跨洋撤单延迟 = 把挂单当固定靶给 bet365 informed flow 打。激励 $0.5–15/场 救不回被扫 $20–60/场。**P1 应改为: 先上套利 (引擎2) + CLV 验 alpha, 做市激励只在"已验证价格平静 + 厚簿 + 远离事件窗"的市场作为 carry 叠加, 且必须带撤单触发器 (引擎3 的最小子集)。**

5. **BE 修正: maker 零费把套利出场腿 BE 从中价 2.8% 砍到约 1.4%–1.8%** (省往返 fee 的一半 75bps + 出场腿半 spread 转为赚 spread). 但**前提是出场腿真能 maker 成交** (非时间敏感腿才行, 时间敏感的进场腿仍须 taker). 纯做市的 sizing **不是 Kelly-edge, 是"激励收益率 vs 库存 VaR"的约束优化**, 公式见 §4.2.

## 1. 重审「排除做市」: 双边激励做市净期望模型

### 1.1 把草案引擎1的收益拆成可算的项

草案说 E[做市净收益] = 激励份额 + rebate − 逆向选择损失. 我把它写成**每单位时间、每市场、每边**的期望 (单位: USDC):

```
E[做市净/单位时间] = R_incentive + R_rebate + R_spread_capture − L_adverse − C_inventory

其中:
  R_incentive  = (Q_我 / Q_全体) × Pool_per_game_per_epoch        # pro-rata 激励, 二次打分
  R_rebate     = maker_fill_volume × taker_fee_rate × 0.20~0.25  # taker 费返 maker
  R_spread_capture = (被动成交量) × 半spread × P(非逆选成交)       # 赚 spread 的部分
  L_adverse    = (逆选成交量) × E[move | 逆选]                    # 被 informed flow 扫
  C_inventory  = 库存持有期 × σ_mid × 持仓量 × 风险价 (库存方向风险)
```

**关键洞察: R_spread_capture 和 L_adverse 是同一笔被动成交的两面。** 一笔挂单被吃, 要么是 uninformed 对手 (我赚半 spread, 进 R_spread_capture), 要么是 informed 对手 (价格马上对我不利, 进 L_adverse). 做市净期望的成败全在这两类成交的**混合比例** + **逆选那笔亏多少**.

这正是 round-1 §1-(b)第1条的量化版: **做市赚钱要求 P(uninformed) × 半spread > P(informed) × E[move|informed]。** 激励池在等式左边加了 R_incentive 这个常数项补贴, 但**右边的 L_adverse 一点没变**。

### 1.2 逆向选择损失 L_adverse 估算 (跨洋是命门)

**逆选发生的物理链条:**
1. bet365 in-play 在进球/得分后**毫秒–秒级**重定价 (sharp).
2. 我们的挂单还停在旧价 (stale).
3. informed taker (别的快 bot, 或被新信息驱动的散户聚合) 穿价吃掉我们的 stale 挂单.
4. 我们想撤, 但跨洋 RTT **200ms ± 50ms** (laojiang §3 实测 US→AWS Polygon/CLOB), 且**心跳 10s** 才一轮 (clob-wss-heartbeat memory). 撤单指令到达前, 挂单已被吃.

**被扫一次的损失:** 我们以 stale 价成交, 真值已经移动. 损失 = |成交价 − 新公允价|. 对一次进球类事件, sharp 重定价幅度 round-1 实测约 **2%–5%** (12s 时滞错价幅度). 我们挂在中点附近, 被扫那边的损失约 **半个 move 到一个 move**:

```
L_per_sweep ≈ (move_幅度 / 2 + 半spread) × 该边挂单 notional
            ≈ (0.03/2 + 0.005~0.01) × notional
            ≈ 2.0%~2.5% × notional      # 单次被扫, 中价区
```

**被扫频率:** 进球类事件每场足球约 2.7 个进球 + 多次危险进攻 (准进球波动), 网球每局都有分数跳. 保守按**每场每边 2–4 次有效逆选成交**. 注意: 我们双边挂单, 信息冲击**只打一边** (利好 YES 时 YES 挂单被抬走/NO 挂单被砸), 所以每次事件**至少有一边被逆选**.

```
L_adverse/场/边 ≈ 2~4 次 × 2.0%~2.5% × notional_per_side
              ≈ 4%~10% × notional_per_side       # 每场, 单边
```

若单边挂 $1000, **逆选损失 $40–$100/场/边**. 这是 round-1 "做市与 edge 前提矛盾" 的现金标价.

> **跨洋是放大器, 不是边缘因素。** 同地做市商撤单 < 5ms, 能在 bet365 跳后、informed taker 到达前撤掉绝大部分 stale 挂单, 把 L_adverse 压到接近 0. 我们 200ms+10s 心跳, **撤单几乎永远跑不赢**进球瞬间的 informed flow. 这是结构性劣势, 钱买不回 (除非把节点搬到撮合机房, 当前不可能).

### 1.3 R_rebate + R_spread_capture (平静期收益)

平静期 (无事件、价格稳) 的被动成交大多是 uninformed (有人调仓/进出场), 这部分我们赚:
- R_spread_capture: 半 spread × uninformed 成交量. 中价区半 spread ~0.5%–1%.
- R_rebate: taker 费 (体育峰值 0.75%) 的 20–25% 返给 maker = **0.15%–0.19% × 被动成交 notional**.

平静期这两项是**正的且无逆选**, 这是做市唯一干净的钱. 但平静期成交量小 (没人急着交易), 且**这恰恰不是我们有信息优势的时刻** —— 平静期我们和所有人一样瞎, 赚的是纯流动性补偿 (round-1 排序里的 (b), 低 alpha 依赖).

### 1.4 激励 pro-rata 份额粗算 (大鲸鱼稀释)

二次打分 `S(v,s) = ((v−s)/v)² × b`, 奖励 = `Q_我_epoch / Q_全体_epoch × Pool`. 关键是**分母 Q_全体被专业做市商主导**.

**数量级粗算 (保守):**
- 池: $5M/月 ÷ 30 天 ÷ (体育电竞活跃 game 数, 保守按 500 game/天 同时挂激励) ≈ **$330/game/天** 量级 (赛前+盘中合池前的粗口径; 实际单个热门 game 池更大、冷门更小).
- 我们的 Q 占比: 二次打分下, 贴中点 (s→0) 拿满分, 但**份额是 size 加权的**. 专业做市商单边挂 $50k–500k, 我们 MVP 挂 $1k–10k.
  - 单 game 全体做市 notional 假设 $200k–2M (热门盘), 我们 $2k 双边 → 占比 **0.1%–1%**.
  - 即便我们贴得比鲸鱼更紧 (二次加成), 二次项最多把我们的有效 Q 放大 ~2–3x (c=3 双边满分 vs 单边 1/3), 占比顶到 **0.3%–3%**.
- → **R_incentive ≈ 0.3%~3% × $330 ≈ $1~$10/game/天**, 乐观热门盘到 **$15/game/天**.

**对照 §1.2 的逆选损失 $40–100/场/边: 激励 $1–15 救不回逆选 $40–100。** 数量级差一档. 这就是数字给出的判决:**在有 informed flow 的 in-play 时刻, 激励补贴远不足以覆盖逆选损失。**

> **pro-rata 的残酷性**: 池是固定的 $5M, 越多人挤 (尤其专业鲸鱼), 我们份额越小. 我们用 size 抢份额 = 放大库存 + 逆选敞口去抢一个被稀释的小补贴. **这是负杠杆**: 为多领 $X 激励要多挂 size, 多挂 size 多挨逆选 $Y, 而 Y > X.

### 1.5 净期望分区结论

把 §1.2–1.4 合成, 做市净期望**按市场状态分区**, 不是一个数:

| 市场状态 | R_incentive | R_spread+rebate | L_adverse | 净期望 | 判决 |
|---|---|---|---|---|---|
| **平静期 + 厚簿 + 远离事件** | $1–15/天 | 正 (uninformed 流) | ≈ 0 | **正 (薄)** | 可做 carry |
| **进球/得分事件窗 (±30s)** | $1–15/天 | 被逆选覆盖 | $40–100/场/边 | **显著负** | 必须撤单/不挂 |
| **薄簿冷门盘** | 池小份额大但绝对值小 | spread 宽但成交稀 | 单次扫损失大 | **负 (方差大)** | 禁 (round-1 流动性陷阱) |

**→ "排除做市" 修正为: 排除"无差别广覆盖做市"(草案引擎1原形态), 保留"价格平静期 + 厚簿 + 事件窗外"的 carry 型做市, 且必须带撤单触发器。** 激励不是"把成本方变利润方", 是"给本就微正的平静期 carry 加一层薄补贴"——不足以支撑把做市当主引擎.

## 2. 双引擎主次: 草案主次倒置, 必须翻转

### 2.1 金融判断: 套利是主, 做市激励是副

**草案立场**: 引擎1激励做市 = 广覆盖主引擎 (不依赖预测), 引擎2套利 = 深叠加.

**我的反驳 (金融经济逻辑)**:

**(1) 同一信息优势在两个引擎里方向相反 —— 这是决定性论据。**
- 引擎2套利: 我们用信息速度优势**主动吃别人的 stale 挂单** (站 informed/taker 一方, 赚时滞).
- 引擎1做市: 我们**被动挂单等着被别人吃** (站 uninformed/maker 一方, 进球时被 informed flow 反扫).
- **我们最有价值的资产是"比 PM 散户快 12s 看到 sharp"。引擎2变现这个资产, 引擎1把这个资产送给对手。** 让同一个团队同时做两件方向相反的事, 在进球时刻引擎2想吃单、引擎1的挂单正在被扫, **自己跟自己的信息优势对冲**.

**(2) alpha 的"真伪"层级不同。**
- 套利 edge = 信息时滞, 是**真 alpha** (有方向性预测价值, 可被 CLV 尺子验证, 是承担 informed 角色赚的钱).
- 做市激励 = **补贴 + 流动性补偿**, 不是 alpha (是承担 uninformed 库存风险 + 平台撒钱). 补贴可以拿, 但**靠补贴活的策略不是 quant alpha, 是补贴套利**, 补贴一停 (平台改规则/池缩水) 立刻归零. $5M/月是平台 2026-04 起的促销, 不是结构永续.

**(3) 规模与可持续性。**
- 草案担心套利"$5–50/天天花板低"(legacy doc C 节). 但这是**当前覆盖受限** (只 tennis/soccer 有 sharp) 的天花板, 不是套利机制的天花板. 扩 sharp 覆盖 (A1-3 缺口) 直接抬这个天花板, 是**真 alpha 的线性扩展**.
- 做市激励的天花板是 pro-rata 池份额, 我们想多拿就得多挂 size = 多挨逆选 (§1.4 负杠杆). **靠加 size 抢补贴是不可持续的, 越抢越亏。**

### 2.2 正确的引擎关系

```
主引擎 = 引擎2 (信息时滞收敛套利)               ← 真 alpha, 团队信息优势的正确变现方向
  ├─ 进场腿: taker 吃单 (时间敏感, 必须快)
  └─ 出场腿: maker 挂单 (非时间敏感) → 在这里顺便:
       ① 省 fee (零费) + 半 spread 转赚              ← BE 砍到 1.4–1.8% (§4.1)
       ② 出场挂单期间若够 min_incentive_size 顺手领激励   ← 副产品, 不专门为它挂

副引擎 = 平静期 carry 做市 (引擎1降级形态)         ← 补贴层, 非主引擎
  · 仅在 已验证价格平静 + 厚簿 + 事件窗外 的市场
  · 必须带撤单触发器 (bet365 跳 → 立即撤/不挂)
  · sizing 按库存 VaR 约束 (§4.2), 不抢份额
  · 净期望目标: 微正即可 (补贴 + 平静期 spread), 不亏即赚 (摊薄固定成本)
```

**一句话**: 把做市激励**寄生在套利出场腿上** + **平静期低风险 carry**, 而不是独立开一条"广覆盖做市主引擎"去用信息优势补贴对手.

## 3. 攻草案的具体漏洞

### 3.1 漏洞1: P1 "先上无模型规则化做市" 会被逆选吃爆 (反对)

**草案 P1**: 引擎1规则化做市, 立即跑, 赚激励, 不需模型.

**攻击**: 规则化做市 = 按固定规则贴中点双边挂单. **没有避险大脑 = 挂单是固定靶**:
- bet365 进球跳价时, 规则化做市不知道要撤 (它没接事件信号), 挂单原地被扫.
- 跨洋 200ms + 10s 心跳, 即便接了信号, 撤单也慢 (§1.2).
- 数字: 逆选 $40–100/场/边 vs 激励 $1–15/场. **每场每边净亏 $25–85**, 一天几十场 = 系统性失血, 比 round-1 那笔 paper −$15 出血更快.

**这正是 round-1 "why-no-trades fee 流血" 教训的做市版**: 没有 alpha/避险大脑的自动挂单 = 喂给 informed flow.

**修正**: P1 不能是"裸规则化做市". 要么:
- (a) P1 = 套利引擎2 + CLV 验 alpha (我 round-1 的建议, 仍成立);
- (b) 若一定要先跑做市拿数据, 必须**至少带最小撤单触发器** (bet365 价跳 Δ > 阈值 → 立即撤该市场全部挂单 + 进入冷却), 即引擎3的最小子集. **撤单触发器是做市的安全带, 不是可选增强。** 跨洋下安全带也漏 (撤单延迟), 所以还要叠 "事件窗内不挂" 的 fail-closed.

### 3.2 漏洞2: 引擎1 vs 引擎2 抢同一资金/同一市场 = 内耗 (确认存在)

**机制冲突 (信 verified doc §3)**: 同一市场 YES+NO 限价单**共用同一 balance reserve** (挂单总和 ≤ 可用余额). 引擎1要双边挂 (占 reserve), 引擎2要留余额吃单 (taker 需要 free balance). **在同一市场, 引擎1的挂单占用会饿死引擎2的吃单能力**, 反之亦然.

**经济内耗 (更严重)**: §2.1(1) 已述 —— 进球时刻引擎2想 taker 吃低估边, 引擎1的 maker 挂单正被反向扫. **同一资金, 一边在赚时滞, 一边在亏时滞, 净额被抵消**, 还付两边的库存/敞口风险.

**修正 (资金/市场隔离规则, 给老韩 enforce)**:
1. **同一 condition 内, 引擎1和引擎2互斥**: 一个 condition 在某时刻只能由一个引擎持有挂单/仓位. 套利信号触发 → 该 condition 切引擎2模式 (撤掉引擎1做市挂单, 释放 reserve 给吃单). 平静回落 → 可切回引擎1 carry.
2. **资金池物理分账**: bankroll 切两个子账 `B_arb` (引擎2吃单弹药) + `B_mm` (引擎1做市库存), 各自独立 cap, 防互相挤占. 比例建议初期 `B_arb : B_mm = 70 : 30` (主引擎拿大头).
3. **事件窗 = 引擎2 独占**: 进球/得分事件窗 (±30s) 内, 该 condition 强制只允许引擎2, 引擎1禁挂 (这同时是 §3.1 的安全带).

### 3.3 漏洞3: 草案把"绕开 long-only/split-merge 缺失"当优势, 但双 buy 锁不住差

草案引擎1说"双边 BUY YES + BUY NO 都是买, 绕开做空限制". 金融上提醒: **双 buy YES+NO 在 a+b≥1 时 (常态) 不是套利, 是零敞口 + 双库存占用**. 只有 a+b<1 的瞬间双买才锁无风险差 (round-1 §2.1), 那是稀有事件 (<50ms bot 秒杀, 跨洋抢不到). 所以"双 buy 做市"的收益**纯来自激励 + 平静期 spread**, 没有"双买锁差"这层额外保护. 草案别把"绕开做空"读成"多了一层安全". 它只是合规可行, 不增加 edge.

## 4. 修正 BE / sizing

### 4.1 maker 零费把 BE 砍到多少

round-1 §5.1 中价 taker/taker BE ≈ 280 bps. 拆解 maker 零费的影响 (**只对能走 maker 的出场腿生效**):

| 成分 | round-1 taker/taker | maker 出场修正 | 说明 |
|---|---|---|---|
| fee 进 (taker, 时间敏感) | 75 bps | **75 bps** | 进场腿必须 taker (要快), 不变 |
| fee 出 (出场腿) | 75 bps | **0 bps** | maker 零费 ✓ (verified §1) |
| 半 spread 进 (taker 穿价) | 50 bps | 50 bps | 进场吃单, 付半 spread |
| 半 spread 出 (出场腿) | 50 bps | **−50 bps (赚)** | maker 挂单**赚**半 spread 而非付 |
| 滑点 | 30 bps | 30 bps | 不变 |
| taker rebate (出场不适用, 进场我们是 taker 付费) | 0 | 0 | rebate 给 maker, 进场我们是 taker |
| **BE 合计** | **280 bps** | **105 bps** | **砍 62%** |

**修正 BE (中价, 套利出场走 maker): ≈ 105–140 bps (1.05%–1.4%)**, 取决于出场 maker 是否真成交 (成交率 < 1 要留缓冲, 故取 140 bps 偏保守). 极价区更低 (fee 进一步降).

> **这把 round-1 的"边际薄"结论实质改善了。** round-1 说"必须把 BE 从 2.8% 压到 < 2% 才有稳定肉", 现在 maker 零费**直接做到 1.4%**. 对照错价幅度 2–5%, **净 edge 从"勉强 0.2%"变成"1–3.6%", 安全边际从薄变厚。** 这是激励/零费机制对方案最大的正面贡献 —— **但它作用在套利出场腿上, 不是支撑独立做市引擎。**

**修正 BE 阈值表 (给信号门):**

| 场景 | 进场 | 出场 | BE | 触发错价门 (net>0) | 留 0.5% 安全边际门 |
|---|---|---|---|---|---|
| 套利, 中价, 出场 maker | taker | maker | **140 bps** | > 1.4% | **> 1.9%** |
| 套利, 极价, 出场 maker | taker | maker | **~80 bps** | > 0.8% | **> 1.3%** |
| 套利, 中价, 双 taker (出场抢时间) | taker | taker | 280 bps | > 2.8% | > 3.3% |

**实现规范**: `arb_signal.hpp` 的 BE 计算需按"出场腿模式" (maker/taker) 分档. 出场走 maker 时 fee_out=0 且 spread_out 符号翻正 (赚). 默认假设出场 maker (BE=140bps), 但若 `OpenLegLedger` deadline 临近强平 (必须 taker 抢时间), BE 回退到 280bps 重算净 edge —— **deadline 临近的强平腿可能从正变负, 这要进风控告警**.

### 4.2 做市激励的 sizing 逻辑 (不是 Kelly-edge)

**核心: 做市 sizing 不能用 Kelly-edge 公式。** Kelly 的前提是"有正 edge 的重复下注", 但平静期 carry 做市的 edge 是补贴 + spread (微正且不稳), 进球时是负 edge. 用 Kelly 会在"激励看起来 edge 正"时过押, 进球时被扫爆.

**正确框架: "激励收益率 vs 库存 VaR" 的约束优化** (做市商标准范式, Avellaneda-Stoikov 简化版):

```
做市报价 size 决策, 不最大化 Kelly 增长, 而是在 库存风险预算 内最大化激励收益率:

max   R_incentive(Q) + R_spread(Q) − L_adverse(Q)
 Q
s.t.  库存 VaR 约束:  Q × σ_mid × z_99 ≤ VaR_budget_mm        # 库存方向风险有界
      逆选预算:       Q × P(event_window) × E[move] ≤ L_budget  # 被扫损失有界
      reserve 约束:   Q_YES + Q_NO ≤ B_mm                       # 共用余额 (verified §3)
      激励资格:       Q ≥ min_incentive_size, s ≤ max_incentive_spread

库存偏移 (Avellaneda-Stoikov 风格): 报价中心随净库存偏移
  reservation_price = mid − inventory × γ × σ²                 # 库存多 → 报价偏低引导卖出
  γ = 库存厌恶系数 (跨洋高延迟下 γ 要调大, 因为撤单慢, 库存更危险)
```

**关键数字 (库存 VaR 反推单边 size 上限):**
- 设 B_mm = 30% × bankroll. 平静期 σ_mid (1min) 经验 ~0.5%–1% (厚簿稳价).
- 库存 VaR 约束: 单 condition 库存方向损失 (1min, 99%) ≤ 0.5% bankroll.
- → `Q_单边 ≤ 0.5%·bankroll / (σ_mid × z_99) = 0.5%·B / (0.008 × 2.33) ≈ 0.27·B` 名义上限, 但被 §4.2 的 L_budget (逆选预算) 进一步压低.
- **逆选预算才是真约束**: 单 condition 单场逆选损失 ≤ 0.3% bankroll → `Q_单边 ≤ 0.3%·B / (期望被扫次数 × move/2) = 0.3%·B / (3 × 0.015) ≈ 0.067·B`. **逆选预算把 size 压到库存 VaR 的 1/4。** 这量化了"做市不是 Kelly 放大, 是逆选约束收缩".

**做市 sizing 实现规范:**
1. **不调用 arb_sizing (Kelly).** 新建 `mm_sizing`: 输入 (σ_mid, P(event_window), E[move], B_mm, min_incentive_size), 输出受双重 VaR 约束的 Q. 取 `min(库存VaR上限, 逆选预算上限, reserve上限)`.
2. **激励收益率门**: 只在 `R_incentive(Q) + R_spread(Q) > L_adverse(Q)` 预估为正时挂. 进球窗内 L_adverse 预估暴增 → 门自动关 (= §3.1 安全带的量化形式).
3. **库存偏移报价**: 净库存非零时, reservation price 偏移引导对称化, 防单边库存累积成方向赌.

### 5.3 上线前必验 (paper 期, 数字说话才放真钱)

1. **CLV 尺子验套利 alpha 真实存在** (round-1 §4.3, 最低方差验证) —— 主引擎的生死前提, 优先级最高.
2. **实测 §1.2 逆选频率 + §1.4 激励份额真值** —— paper 期挂小额做市单, 实测被扫频率、被扫损失、实领激励. **这是验证副引擎该不该开的唯一依据。** 我 §1 的数字是粗算, 实测可能更好 (厚簿稳价市场逆选低) 或更糟 (informed flow 比估计密). 不实测不开真钱做市.
3. **实测出场 maker 成交率** —— BE=140bps 假设出场 maker 成交. 若成交率低 (挂单等不到对手), 大量出场腿被迫 taker 强平 (BE 回 280bps), §4.1 优势打折. 需实测成交率分布定 deadline buffer.
4. **σ_mid (平静期) + σ_Δmid (套利) 的 conformal 校准** (round-1 §3.6) —— 两个 sizing 公式的分母, 没校准全错.

### 5.4 一句话给老雷

**激励池没推翻"排除做市", 它推翻的是"做市恒亏"的绝对结论 —— 把做市从"必排除"改成"窄区间可做的补贴层 carry"。** 但草案"激励做市当广覆盖主引擎"是金融上的主次倒置: **用我们最贵的资产 (12s 信息速度) 去补贴对手挨逆选, 抢一个被鲸鱼稀释到 $1–15/场的小补贴, 是负杠杆。** 真 alpha 是套利, 做市激励寄生在套利出场腿 (零费把 BE 砍到 1.4% 是真利好) + 平静期低风险 carry. **先上套利 + CLV 验 alpha, 做市带着撤单安全带在平静厚簿区做补贴, 实测逆选/激励真值后再定 B_mm 规模。**
