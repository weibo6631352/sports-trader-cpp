## 0. TL;DR — 核心变化

**v7 现状:** 4 页 (盯盘/Ops/PnL/市场详情), 盯盘页每个 Event 完全展开, 单卡高度 >600px, 一屏只能看 2-3 张赛事卡。

**v8 变化:** 盯盘页引入折叠优先, 默认一行摘要 (~40px), 点击展开看全档位+量化+AI+拒单。一屏可见 15-20 个市场行。Ops / PnL / 市场详情页保持 v6/v7 结构不变。

**老板核心:** 主页默认折叠 → 点击展开 → 参考 Polymarket 官方 portfolio 页的"positions 列排列+PnL 配色+市场详情抽屉"体验。

## 1. 折叠优先的体感逻辑 (为什么这么设计)

v5.2 验收报告记录的核心痛点:

- 单张赛事卡高度 >600px: 量化区 + 双边订单簿 + 持仓三段全展开
- 主盘需要大量纵向滚动: 1440p 下约 2-3 张赛事卡可见
- 操作员无法不滚动就知道当前监控几场比赛

折叠优先解决的是: **信息密度可控 + 异常快速扫描**。

Polymarket 官方 portfolio 页的参考体验: 每个持仓一行 (市场名 + 方向 + 价格 + PnL), 点击行展开看完整仓位详情和订单记录。主列表页是纯扫描视图, 展开层是决策视图。这个交互模式完全适用于操作员盯盘场景。

操作员两种工作模式:

1. **扫描模式 (90% 时间):** 一眼扫全部市场, 寻找异常 (红色 edge / 大拒单数 / 延迟告警)。折叠态满足此需求: 一行 40px, 一屏 15-20 个市场。
2. **深挖模式 (10% 时间):** 发现某个市场有异常 → 展开看双边订单簿全档 + 量化全字段 + AI 出处。展开态满足此需求: 单市场完整信息, 不影响其他行。

## 3. 盯盘页 (Trading) — v8 折叠/展开重设计

### 3.1 层级结构

```
盯盘页
└─ Event (赛事分组, 可折叠)
     ├─ 赛事摘要行 (默认可见, 常驻)
     └─ Market 行列表 (sports_market_type)
          ├─ Market 摘要行 [折叠态, 默认] — 一行 ~40px
          └─ Market 展开区 [展开态, 点击触发]
               ├─ 双边订单簿全档 (5档)
               ├─ 量化全字段 (fair/edge/kelly/signal/CI)
               ├─ AI 参数区 (model_id/confidence/advisory)
               ├─ 持仓/PnL
               └─ 拒单明细
```

### 3.2 摘要行显示字段 (折叠态)

**摘要行是操作员的"扫描载体", 字段选取原则: 一眼判断是否需要展开。**

每行约 40-44px 高度, 固定单行不折行。

```
[▶] [盘口标签]  [队伍/盘口名]  [最优买价]  [最优卖价]  [edge bps]  [持仓]  [浮盈]  [拒单]  [延迟]
```

| 列 | 内容 | 宽度 | 颜色规则 |
|---|---|---|---|
| 展开箭头 | ▶ (折叠) / ▼ (展开) | 24px | 灰色 |
| 盘口标签 | 胜负/让分/大小 (SUID Chip) | 56px | 蓝/橙/紫 区分类型 |
| 市场名 | 赛事队名 + 盘口数 (截断) | flex 1 | 白色 |
| 最优买 | best_bid (0.xxx) | 72px | 绿色 (bid 语义) |
| 最优卖 | best_ask (0.xxx) | 72px | 红色 (ask 语义) |
| Edge | edge_bps, 带符号 | 72px | 正=绿/负=红/0=灰 |
| 持仓 | YES Nk / NO Nk 或 "无持仓" | 88px | 有持仓=白/无=灰 |
| 浮盈 | pnl_unrealized, 括号负数格式 | 80px | 正=绿/负=红 |
| 拒单 | ×N (N>0 红色角标) | 40px | N>0 红/N=0 灰 |
| 延迟 | staleness ms, 三色 | 56px | <100ms绿/100ms-1s黄/>1s红 |

**设计决策 — 不在摘要行显示的字段:**

- model_fair_value: 展开态看, 摘要行只给 edge 结果
- kelly_fraction / suggested_notional: 展开态看
- 双边订单簿档位: 展开态看
- AI model_id / confidence: 展开态看
- 4 时间戳瀑布: 展开态看

### 3.3 展开区内容 (展开态)

点击摘要行的任意位置 (或展开箭头) 触发展开, 同一 Event 下允许多个 Market 同时展开。

### 3.6 Event 分组折叠

Event 分组 (赛事级) 也支持整组折叠/展开:

- **进行中赛事:** 默认展开分组 (赛事头可见 + 旗下所有 Market 行可见), Market 行各自折叠
- **预赛/结束赛事:** 默认折叠整组 (只显示赛事摘要头一行)
- 点击赛事头的 ▶/▼ 切换整组折叠状态

Event 分组头内容:

```
[▼/▶] [运动图标] 主队 vs 客队   比赛类型   [进行中: 节次 时钟 比分] 或 [预赛: 开赛时间]   ●延迟
```

赛事头不含量化数据, 只做分组导航用。

### 3.7 交互规则

| 操作 | 效果 |
|---|---|
| 点击 Market 摘要行 | 切换该 Market 的折叠/展开状态 |
| 点击 Event 分组头 | 切换整个 Event 分组的折叠/展开状态 |
| 同一 Event 下多个 Market 同时展开 | 允许, 各自独立控制 |
| 跨 Event 展开 | 允许, 无限制 |
| 筛选切换 (全部/进行中/有持仓) | 保留当前各行展开状态, 只改可见行集合 |
| 刷新轮询 (5s) | 保留展开状态, 数据原地更新 (不触发折叠) |
| 搜索赛事 | 过滤分组, 保留匹配分组的展开状态 |
| 页面初次加载 | 所有 Market 行默认折叠; 进行中赛事分组默认展开 |

**展开状态持久化:** 展开状态存储在前端 SolidJS store (per condition_id 的 expanded: boolean), 轮询刷新不重置。建议存 sessionStorage 防止偶发刷新丢失状态。

## 4. SUID 组件选型

v7 已确认使用 SUID (SolidJS 版 Material Design)。v8 折叠/展开新增以下组件使用:

### 4.1 主要组件

| 功能 | SUID 组件 | 备注 |
|---|---|---|
| 摘要行列表容器 | SUID `Table` + `TableBody` + `TableRow` | 每个 Market 一个 TableRow, 支持 click handler |
| 展开区 | SUID `Collapse` (配合 TableRow 下方额外行) | `in={expanded()}` prop 控制展开状态 |
| Event 分组折叠 | SUID `Accordion` + `AccordionSummary` + `AccordionDetails` | Event 头作为 AccordionSummary, Market 行列表在 AccordionDetails |
| 盘口类型标签 | SUID `Chip` | 胜负/让分/大小 三种颜色区分 |
| 拒单角标 | SUID `Badge` | N>0 时红色 badgeContent |
| 市场详情抽屉 | SUID `Drawer` (右侧滑出) | 从摘要行点击"详情"按钮触发, 替代 v6 的市场详情页跳转 |
| 筛选下拉 | SUID `Select` + `MenuItem` | 全部/进行中/有持仓 |
| 刷新间隔选择 | SUID `Select` | 5s/10s/30s |
| 搜索框 | SUID `TextField` | 本地 filter, 不发请求 |

### 4.2 Accordion 用于 Event 分组

```
<Accordion expanded={eventExpanded()} onChange={...}>
  <AccordionSummary expandIcon={<ExpandMoreIcon/>}>
    [赛事摘要: 队名/比分/节次/延迟]
  </AccordionSummary>
  <AccordionDetails>
    <Table>
      <TableBody>
        <For each={markets()}>
          {(market) => (
            <>
              <TableRow onClick={toggleMarket(market.id)} hover>
                [摘要行: 盘口标签/名称/最优价/edge/持仓/浮盈/拒单/延迟]
              </TableRow>
              <TableRow>
                <TableCell colSpan={10} style="padding: 0">
                  <Collapse in={expanded(market.id)} timeout="auto">
                    [展开区: 双边书 + 量化AI + 持仓拒单]
                  </Collapse>
                </TableCell>
              </TableRow>
            </>
          )}
        </For>
      </TableBody>
    </Table>
  </AccordionDetails>
</Accordion>
```

### 4.3 Collapse 用于 Market 行展开

SUID `Collapse` 组件的 `in` prop 绑定 SolidJS `createSignal`:

```
const [expandedMarkets, setExpandedMarkets] = createStore<Record<string, boolean>>({});

const toggleMarket = (conditionId: string) => {
  setExpandedMarkets(conditionId, (v) => !v);
};
```

`Collapse` 的 `unmountOnExit` 设为 false (保留 DOM 节点, 避免折叠后订单簿数据丢失, 轮询状态维持)。

### 4.4 Drawer 用于市场详情 (替代市场详情页)

点击 Market 摘要行最右侧的"详情"按钮 (或双击行) 触发右侧 Drawer 滑出, 展示完整市场详情:

- 全档位订单簿 (10-20 档)
- 单笔决策 trace
- 订单生命周期
- 结算状态

Drawer 不影响主列表的折叠/展开状态, 是叠加层。

## 5. Polymarket 官方 portfolio 参考映射

Polymarket portfolio 页的体验元素 → v8 的对应设计:

| Polymarket portfolio 元素 | v8 对应设计 |

| 点击行展开看完整持仓详情 | 点击 Market 摘要行展开 Collapse 区 |
| 右侧市场详情抽屉 | SUID Drawer 从右侧滑出 |
| positions 列排序 (按 PnL/市场名) | 筛选栏支持排序: 按 edge/浮盈/延迟排序 |
| 市场类型 Tag (标签区分) | SUID Chip 标签: 胜负(蓝)/让分(橙)/大小(紫) |
| 折叠默认 = 一屏看更多 | 默认折叠态: 一屏 15-20 行 vs v5.2 的 2-3 张卡 |

**核心差异 (内部交易系统 vs 公开 portfolio):**

Polymarket portfolio 只有持仓行, 我们的摘要行需要同时展示 **无持仓但在监控** 的市场 (用于观察 edge/机会)。无持仓行的持仓列显示 "—" (灰色), 浮盈列空白。

## 6. 信息密度对比 (v5.2 vs v8)

| 维度 | v5.2 (完全展开) | v8 (折叠优先) |
|---|---|---|
