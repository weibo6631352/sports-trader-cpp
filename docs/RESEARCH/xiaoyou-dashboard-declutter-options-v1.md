# UX 去杂乱布局方向 — Dashboard v4 declutter options
owner: 小尤  
last_review: 2026-05-29

---

## 一、诊断：v4 为什么看着乱

看完截图 + 代码后，"乱"不是信息太多，是**组织方式让眼睛不知道从哪读、从哪停**。具体病根：

### 1. 比分条重复出现，但属于同一场赛事
截图里 LAL-BOS 的赛况栏（"LAL 87 — 81 BOS | 第 4 节 进行中"）在该赛事的三个盘口（ml / total / spread）上**各出现一次**。相同信息重复三次，占据三排宝贵空间，也让视线无法识别"这三个盘口属于同一场赛"的归属关系。

### 2. 每张卡片结构层级完全等权，没有视觉主次
卡片 header（market-id）/ 比分条 / 盘口元信息 / 量化决策 / 双边订单簿 / 持仓，六个区块都用了几乎相同的字号（10-13px）、相近的背景色（#0d1117 / #161b22 / #21262d 三档极接近），形成视觉上的"灰毯"：每个区块都想"被看见"，结果是都没被看见。

### 3. 量化决策区与订单簿区纵向堆叠，双边宽度被压缩
`quote-section` 在 `dual-book-block` 内部，先占一行（公允价 / 中间价 / 优势 / Kelly / 信号），然后才是并排的两列订单簿。两列订单簿因卡片宽度限制（minmax 400px），每半边只剩约 180px，深度档数字已经开始溢出或换行。

### 4. 颜色竞争点过多
绿色（bid price / 接单中 / stale-ok / wss-ok / state-running / 持仓正 PnL / vig-low）在同一张卡片里同时出现 6-8 处，红色同理。眼睛以为"绿色 = 危险/重要"，但到处都是绿，语义失真。

### 5. 标签层次与信息层次不匹配
"双边订单簿" block-label（10px 大写灰字）的视觉权重低于它下面的 bid-price（13px 粗绿字）。正确的信息层级应该是：赛事 > 盘口类型 > 量化决策（买/不买）> 订单簿细节。但现在视觉上 bid-price 先跳出来，读者的注意力先被价格抓走，然后才回头找"这是什么盘口"。

## 二、三个去乱方向

---

### 方向 A — 赛事分组卡（Event Group Card）

**核心手法：** 把同一赛事的多盘口收归一个"赛事块"，赛事头（比分 + 球队 + 赛况）只渲染一次；下方横向平铺该赛事的各盘口，每个盘口是一个"瘦子卡"（窄列），双边订单簿在瘦子卡内左右分栏。

**解决了什么：** 消除比分条重复；赛事/盘口/订单簿三层级在视觉上清晰对应；同一赛事的三盘口并排，可横向对比 Kelly / edge。

**双边订单簿在此方向的呈现：** 每盘口列内，垂直分两行（YES 上 / NO 下），各显示 best bid / ask / spread / 深度 3 档。列宽约 200-240px，够用。

**优点：**
- 比分条从"每卡一次"变为"每赛事一次"，视觉噪声立降 66%（三盘口情况下）
- 多盘口横向排列，操作员可一眼看一场赛的所有 Kelly，快速判断哪个盘口值得出手
- 赛事间用深色间隔行分组，滚动时赛事边界清晰

**缺点：**
- 盘口数量不固定（1-5 个），列数动态变化，横向滚动风险（需要 overflow-x 或折行策略）
- 小屏幕友好度最差
- 每列宽度压缩后，订单簿深度展示受限（最多 2-3 档）

**信息密度：** 高，但组织有序。适合双显示器 + 宽屏场景。适合习惯"先看赛事整体再看盘口细节"的操作员。

### 方向 B — 紧凑汇总表 + 右侧详情面板（Summary Table + Detail Panel）

**核心手法：** 主区域是一张多行表格（行 = 每个盘口 / outcome 对），列固定为：赛事/盘口名 | 胜方/双边 Best | 公允价 | 优势(bps) | Kelly% | 持仓 | 拒单。操作员点击某行 → 右侧常驻"详情面板"展开该盘口完整订单簿 + 所有量化参数。**守住"双边同屏"约束**：把 YES best / NO best 放进同一行的两个相邻列，保证不切 tab。

**双边订单簿在此方向的呈现：** 右侧详情面板内，左右分栏（YES 左 / NO 右），中间一条无形价格轴对齐 bid/ask，视觉上能看到双边对称关系。汇总表里则只放 best bid/ask，不展深度，压缩干净。

**优点：**
- 汇总表一眼可对比所有盘口的 Kelly/优势，"哪个盘口值得看"5 秒内扫完
- 详情面板不切页，守住单页约束
- 表格行高约 22px，单屏可显示 15-20 个盘口
- 赛事分组清晰（缩进 + 组头行）

**缺点：**
- 需要"点击"才能看完整订单簿，对需要同时盯多个盘口订单簿的操作员有切换成本
- 右侧面板固定宽度 340px，在 1440px 以下屏幕压缩主表区域
- 不适合"多盘口订单簿同时看，跨盘口比较深度"的场景

**信息密度：** 高（汇总表）+ 按需深入（详情面板）。适合"快速扫盘 → 精确看一个盘口"的工作流。适合习惯交易员工作台风格的操作员。

### 方向 C — 对盘合并视图（Ladder View，中间价格轴）

**核心手法：** 每个盘口用一个"价格阶梯"展示双边，YES 的 bid/ask 在左列，NO 的 bid/ask 在右列，中间是共享的价格轴（0.00 → 1.00）。两边价格镜像对称（因为 YES + NO = 1），vig 一眼看到（两边 ask 之和 - 1）。赛事头和比分仍是每赛事一次，多盘口纵向堆叠。

**双边订单簿在此方向的呈现：** 左右镜像价格梯，中间共享刻度轴。YES bid 从左靠近轴，NO bid 从右靠近轴，ask 在轴附近。公允价作为一条横线叠加在梯图上。操作员可直接看 YES ask 和 NO ask 之间的"vig 空隙"，以及公允价是否在空隙内。

**优点：**
- 对盘视图最直观，vig / 公允价 / 双边对称一眼看出
- 适合做市分析（"我的公允价是否已在盘口报价之外？"）
- 不需要点击，所有信息在单盘口块内一次呈现

**缺点：**
- 每个盘口块高度较高（约 120-150px），屏幕内同时可见盘口数量最少（4-6 个）
- 价格梯只对二元结果有意义（YES/NO），如果未来有多 outcome 市场需重设计
- 实现复杂度最高（需要 SVG 或 canvas 渲染价格轴 + 公允价叠加）
- 操作员需要一点学习时间才能读懂镜像逻辑

**信息密度：** 中（单屏盘口少），但每盘口信息最立体。适合"深度分析一场赛，不需要同时跟多场赛"的做市场景。

## 三、小尤推荐

**推荐方向 A（赛事分组卡）作为 v5 主方案，以方向 B 的"汇总行"作为每盘口子行的头部设计补充。**

理由：

1. **解决最核心的视觉噪声**。比分条重复渲染是 v4 最大的"乱"来源，方向 A 一刀切掉，效果立竿见影。老板看截图第一眼就是"每个卡都一样的赛事头"，这是症结。

2. **守住所有约束**。单页、信息全、双边同屏、赛事→盘口→订单簿层级，方向 A 全部满足，且不需要"点击才能看"。

3. **操作员工作流匹配**。操作员先看"哪场赛有机会"（赛事头的 Kelly/edge 汇总），再横移到具体盘口的订单簿。方向 A 的视线路径天然是先竖后横，符合扫盘直觉。

4. **方向 B 的"汇总行"可作为每盘口块的第一行**，即每列盘口顶部先用一行显示 best bid/ask + 公允价 + Kelly，详细深度在下方展开。这样结合了 B 的快速扫盘能力和 A 的无需点击特性。

方向 C 建议留给"深度分析模式"或未来的悬浮详情弹出，不作为主布局。

## 四、无论选哪个方向，都要执行的通用去乱规则

以下规则与布局方向无关，是排版纪律，任何版本都应执行：

### R1. 比分条只出现一次（每赛事）
`renderScoreBlock` 的调用移到赛事头渲染，不在每个 `renderMarketCard` 内重复调用。这是成本最低、收益最大的单项改动。

### R2. 颜色语义收敛到 3 层
- **行动绿**（`var(--green)`）：只用于正 PnL、Kelly 正信号、双边 bid 价。最多同屏出现 4-6 处。
- **风险红**（`var(--red)`）：只用于负 PnL、拒单、双边 ask 价、gap > 0。
- **暗示黄**（`var(--yellow)`）：只用于警告态（中场、stale warn、vig mid）。
- 其余全部用 `var(--text-dim)` 灰色。现在 wss-ok / stale-ok / state-active / acc-yes 等都在竞争绿色注意力，需要降级为灰色加小点状态图标。

### R3. 字号压缩到 3 档
- **主数值**（bid/ask/Kelly/净PnL）：13-14px mono bold
- **次要标注**（公允价/中间价/深度档/持仓细节）：11-12px mono dim
- **标签/角标**（meta-label/stale chip/demo chip/block-label）：10px 或以下
不要在 10px 和 11px 之间频繁跳跃（现在 style.css 里有 9px/10px/11px/12px/13px/14px 六档，差异过细）。

### R4. 每盘口块内部分区用色块不用边框
现在每个区块（比分/元信息/量化/双边簿/持仓）都用 `border-bottom: 1px solid var(--border)` 分隔，导致卡片里有 5-6 条横线争夺眼球。改为：量化区用浅色底块（`var(--bg3)`），订单簿用 `var(--bg)`（最深），持仓用 `var(--bg2)`，用深浅对比代替线框，留白感更好。

### R5. block-label 视觉权重低于主数值
现在 `block-label`（"双边订单簿"、"持仓/盘口净PnL"）是 10px 大写灰字，但它后面紧跟的 bid-price 是 13px 粗绿字。读者视线先被绿字抓走，再回头找标签，路径错误。修复：标签前加 2px 左侧色条（灰色 `var(--border)`），在空间上"宣示归属"而不增加字号。

### R6. 拒单和 gap 异常用右上角小红点而非内联文字
拒单角标（`.reject-badge`）和 gap 计数目前是内联文字，参与正常文档流，与其他信息混排。改为：卡片或盘口列的右上角 `position: absolute` 小红圆点 + 数字，hover 时展开 tooltip 显示详情。节省行内空间，且红点在视觉上不干扰主阅读路径，只有"出事了"才进入注意力。

### R7. 赛事/盘口头行高固定，不让 flex-wrap 破坏对齐
现在 `.market-info-row` 有 `flex-wrap: wrap`，当 chip 过多时会折行，导致相邻卡片高度不一致，网格对不齐，整体看起来"歪"。改为：每行 chip 优先级排序（状态 > neg_risk > demo），超出部分用 overflow 截断 + "…" 展开 tooltip，保证每行单行显示。
