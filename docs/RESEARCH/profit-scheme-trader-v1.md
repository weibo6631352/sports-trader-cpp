## §0 先把话说在前面 — 一个老操盘手对这套方案的三句判断

1. **这是真活儿，但它是"事件延迟错价"，不是"价格预测"。** 我们不是预测家。真正能吃的 edge 只有一种：**进球/得分发生 → bet365 in-play 价瞬间跳 → PM 散户市场慢 13.2s 才跟上 → 我们在这 ~10s 窗口里抢在散户前面吃。** 任何把它包装成"连续预测未来价格"的版本，实证已经证伪（无事件时 60s 内够本移动只 2.9%，扣费后负期望，详 §2）。**信号要事件闸口，不要连续预测。**

2. **它是补充策略，不是主引擎。** 小袁实测：有效触发每天约 10-50 次，单次净 0.5-2c/share，每日 PnL 量级 $5-$50（不是 $500+）。决定它能不能做大的不是预测精度，是**流动性 + 覆盖率**——我们能挂多深、有多少盘有实时比分。这两个是天花板，模型再好也顶不破。

3. **最大的认知坑：in-play 我们锚的不是"sharp 共识"，是 bet365 单家 square book。** 8-9 家共识只在 pregame（`getodds` 多 bookmaker 数组）。in-play feed（`inplay-<sport>.gz`）的 `bm` 字段实测全场固定 = `"bet365"`，单源。bet365 是 price-maker、square book、vig 4.5-6%，对公众偏好方向（主队/over）系统性低赔。**我们抢的不是"sharp 比 square 聪明"，抢的是"bet365 这家比 PM 散户快"——是速度优势，不是聪明优势。** 这个区别决定了哪些 line movement 能跟、哪些是 bet365 自己的偏见噪声（详 §3）。

## §1 真实操盘手怎么交易这个 — 拿到"信号"后的实际动作

把"未来价格预测信号"翻译成操盘动作。一个老练的双边操盘手脑子里不是"模型说涨我就买"，是一套**进场 / 摆盘 / 库存 / 出场**的肌肉记忆。下面按真实交易流程拆。

### 1.1 这套打法的本质：吃"信息已发生、价格还没到位"的瞬时错价

不是做市（不靠赚价差吃两边），不是方向押注（不赌结算）。是**latency arbitrage 的体育版**：

- t=0：球进了。Goalserve（bet365 源）~2s 内刷出新比分 + 新 value_eu。
- t≈3s：我们感知到（端到端中位 3.1s，小袁实测）。
- t≈3-13s：PM 散户市场还在旧价，做市商还没撤旧单 / 没重新挂。**这是吃单窗口。**
- t≈13s：PM mid 重定价完成（中位），错价消失。我们应该已经进场，正在等平仓。

操盘手的心智模型：**"我手里这一秒，知道一个 PM 上还有人不知道的事实。趁他们的旧单还挂着，吃掉它。"** 这跟做市完全相反——做市是给别人提供流动性赚 spread；这是**主动消耗别人的过时流动性**。

### 1.2 进场：什么时候 taker 穿价、什么时候 maker 挂单

这是整套打法最关键的手感。规则：

**进场永远是 taker（穿价吃单）。** 因为我们吃的是"别人的过时挂单"。事件刚发生时，PM 上还挂着按旧 fair 定的单——领先方 YES 的卖单还停在便宜价，落后方 YES 的买单还停在贵价。**我们要的就是穿过去把这些过时单吃掉。** 挂 maker 单等成交？等你排到队，13.2s 早过了，错价没了，你的挂单变成给别人当对手盘。

具体动作（以"主队进球，买主队 YES"为例）：
```
事件: 主队进球, 比分 0:0 → 1:0
bet365 in-play: 主队 ML value_eu 从 2.10 跳到 1.65 (de-vig fair YES 从 0.46 → 0.59)
PM 现状(旧价): 主队 YES best_ask 还停在 0.48 (做市商没撤)
操盘动作: TAKER 穿价吃掉 0.48 的 ask, 一路吃到 0.52-0.53
        (吃到接近新 fair 0.59 留出 fee+利润空间就停, 不追到 0.58)
```

**出场（平仓）才用 maker 挂单。** 进场吃完后，我背着一个 long YES 仓位，目标是等 PM mid 收敛到新 fair（0.59），在那附近把仓位卖掉锁利。这时候不急（我已经赚了进场到 fair 的差），可以**挂 maker 限价卖单在 target_exit_px**，等散户/做市商重定价上来接我的单。挂 maker 出场还省 fee（taker 3% vs maker 0 + 0.75% rebate）。

> 代码里 `arb_signal.hpp` 已经把这个写对了：`entry_px = is_long ? best_ask : best_bid`（进场吃对手价 = taker），`target_exit_px = entry_px + cons_move`（出场挂到收敛目标）。`position_controller.hpp` 的 reservation 范式也对——限价绝不追价，越过 reservation（净 edge=0 临界价）就不买。**这两个执行核已经是操盘手会同意的形状。**

**例外 — 进场也偶尔挂 maker：** 只有一种情况。错价极大（比如吃到 0.52 离新 fair 0.59 还有 7c）且 ask 深度薄，我担心穿价滑点吃掉 edge，可以**先 taker 吃掉浅层，剩余 size 挂 maker 单在 0.54-0.55**赌 13s 内还有人来撞。但这是 size 管理技巧，不是常规。常规进场 = taker。

### 1.3 双边怎么摆 — "YES/NO 双边" 在 Polymarket 的真实含义

老板说"单市场 YES/NO 双边仓位管理"，操盘手要先把这句话在 Polymarket 机制下翻译清楚，否则会摆错盘。

Polymarket 一个二元市场，YES + NO 互补（YES 价 + NO 价 ≈ 1）。"双边"在我们这套打法里有三种完全不同的含义，**不要混**：

| 含义 | 操盘手叫法 | 我们做不做 |
|---|---|---|
| (a) 同时持 YES long + NO long（锁定无风险价差） | **box / 锁箱** | 极少。只有 YES_ask + NO_ask < 1 - 2×fee 时才存在，PM 上罕见（`x_arb_free_edge` 特征 #105 监控它）。**真出现就闭眼吃，这是无风险套利。** |
| (b) 进场买一边、收敛后卖同一边平仓 | **单边进出（round-trip）** | **这是主路径。** "买主队 YES @0.52 → 卖主队 YES @0.58"。本质单边方向，只是持仓时间极短（10-15s）。 |
| (c) 同时在 YES 和 NO 两个 token 上各建反向仓做对冲 | **delta 对冲 / 腿对腿** | M2 才开。`position_controller` v1 明确"只做多侧，空头 clamp 0"——**结构上现在还开不了真双边对冲。** |

**操盘手给老板的诚实话：** 现在系统能做的"双边"是 (b)——快进快出的单边 round-trip，外加机会主义地吃 (a) 锁箱。真正的 (c) 双边对冲建仓需要 `position_controller` 支持开空（M2）。**别把方案写成依赖 (c)，否则落地时发现做不了。** (b) + (a) 已经足够吃事件错价，不必等 (c)。

**为什么 (b) 单边就够：** 事件错价是**方向性确定**的——主队进球，主队 YES 必涨。我不需要对冲方向风险（方向我知道），我需要的是**时间风险对冲**——怕的是进场后 13s 内没收敛、或者反向再来一个事件（对方立刻回敬一球）。这个用**持仓时限强平**对冲（§1.5），不用 NO 腿对冲。

### 1.4 错价窗口怎么吃 — 一个完整交易场景（带数字）

```
赛事: NBA, 主队领先 88:86, 第4节剩 3:00
事件: 主队命中三分, 88:86 → 91:86 (领先扩大到 5 分)
─────────────────────────────────────────────
t=0.0s   投篮命中 (真实事件)
t=2.1s   Goalserve bet365 源刷新: 主队 ML value_eu 1.40→1.28 (de-vig YES 0.71→0.78)
t=3.1s   我们感知 (端到端中位). 拉 PM book:
         主队 YES: best_ask 0.72 (深度 $180), 0.73 ($90), 0.74 ($60)
         新 fair ≈ 0.78. 错价 = 0.78 - 0.72 = 6c gross.
t=3.3s   BE 检查 (arb_signal): fee_rt ≈ 2×0.03×0.72×0.28 = 1.2c
                              spread = 1c, slip_est ≈ 0.5c
                              BE ≈ 2.7c.  净 edge = 6c - 2.7c = 3.3c > 0 ✓
t=3.5s   TAKER 进场: 吃 0.72($180) + 0.73($90) = $270 notional
                    (吃到 0.73 停手, 不追 0.76; 留 cushion)
                    实际成交均价 ≈ 0.723, 约 374 shares
t=4-13s  PM 散户 + 做市商陆续重定价, mid 爬向 0.78
t=11s    挂 MAKER 卖单 @0.77 (target_exit 留 1c 给对手接单)
t=14s    成交. 卖出 374 shares @0.77
─────────────────────────────────────────────
毛利: (0.77 - 0.723) × 374 = $17.6
减 taker fee 进场: 0.03×0.723×0.277×374 ≈ $2.2
maker 出场: 0 fee (+ 可能 rebate)
净利 ≈ $15  (单次, 一个甜区 NBA Q4 事件)
```

**这个场景为什么成立：** ① NBA Q4 是 hot token（深度尚可、事件冲击大）；② 错价 6c 远大于 BE 2.7c；③ 进场 taker 抢在重定价前；④ 出场 maker 省 fee。**这就是这套打法的理想形态。** 但注意 size 只有 $270——这是流动性天花板（§4），不是策略选择。

### 1.5 库存怎么轮转 — 操盘手最看重的纪律

做这种高频短窗，**库存管理比信号更重要**。死法 90% 是库存爆，不是信号错。规则：

1. **每个仓位背一个"必平时限"（horizon deadline）。** 进场即记 deadline = entry_ts + horizon（墙钟，比如 15s）。到点没自然平掉 → **市价强平**，不管亏赚。`master-plan §4` 的 open-leg fail-safe 就是这个。理由：错价窗口过了之后，我手里的 long YES 就退化成裸方向押注（我又不预测结算），违背初衷。**留过夜的库存 = 把套利做成赌博。**

2. **预测源断流 / stale → 立即清所有 in-flight 仓。** Goalserve 断了、延迟超窗（`RJ-ARB-5 STALE_PREDICTION`），我就是瞎子。瞎子不持仓。

3. **同一 event 的反向事件 = 立即重估，可能要反平。** 主队进球我买了主队 YES，结果 8s 后对方立刻回敬一球——原错价方向反转。这时不能死扛 target_exit，要**当场市价平掉**（哪怕小亏），因为我建仓的前提（领先扩大）没了。这是"reverse line movement"在事件层面的体现（§3.4）。

4. **单 event 敞口上限 + 总在途敞口上限。** `arb_signal` 已有 `horizon_cap_usdc` / `max_open_legs`。操盘手补一句：**不要在同一场球的连续事件里越压越大。** 一场篮球末节可能 30s 内连续得分，每次都是信号，但我连续吃 5 次 = 实际在这场球上压了 5×$270。要设单场球 cap。

5. **轮转节奏：进 → 等收敛 → 平 → 空仓待命。** 理想状态是大部分时间空仓，只在事件瞬间满仓 10-15s 然后立刻清空。**空仓是常态，满仓是例外。** 这跟做市（常年挂双边）相反。

## §2 line movement / sharp money 视角 — 跟还是不跟

这是我的本行。把"bet365 动 → PM 跟不跟、跟多快"拆成可操作的信号取舍。

### 2.1 12s 滞后的真相（实证钉死的数字）

来自 `shorthorizon-locking-feasibility-v1.md`（小董，322k 行 FV 快照实证）：

| 事实 | 数字 | 操盘含义 |
|---|---|---|
| PM 重定价中位延迟 | **13.2s** | 这是窗口上沿 |
| PM 重定价 p25（快的 25%） | **8.5s** | 保守按这个算，别按中位 |
| PM 重定价最快观测 | 2.4s | 最快的盘几乎抢不到 |
| 有可观测重定价的事件占比 | **56.5%** | 43.5% 的事件 PM 根本没反应（无流动性/不敏感）→ 这些盘吃不到 |
| 我们端到端感知 | ~3.1s（小袁） | 留给我们的净窗口 ≈ 8.5-3.1 = 5.4s（p25 口径）到 10s（中位口径） |

**操盘手读这组数字的结论：** 窗口是真的，但**余量薄**。按 p25=8.5s 算，扣掉我们 3.1s 感知，只剩 5.4s 去下单 + 成交。下单 CLOB POST 中位 60ms（新建 TLS）/ 25ms（复用）——链路不是问题，**问题是 3.1s 感知里有 1s 是 Goalserve 自己 2s 刷新一次的不可控延迟。** 所以：**专门的事件触发路径（绕过 500ms 轮询）是兑现这个窗口的硬前提**，不是优化项。这点小袁说透了，我背书。

### 2.2 哪些 line movement 是真信号（跟单）

**真信号 = 事件驱动的 bet365 跳变。** 实证：够本移动里 70%+ 发生在比分事件 10s 内，80% 在 30s 内（小董 §C1）。规则：

| line movement 类型 | 跟不跟 | 理由 |
|---|---|---|
| **进球/得分后 bet365 value_eu 跳变** | ✅ 跟，最强信号 | 信息确定（球真进了）、方向确定、PM 必然滞后 |
| **关键判罚后跳变**（点球、红牌、ace/break point） | ✅ 跟，次强 | 同样是离散事件，方向较确定，但幅度要看盘口敏感性 |
| **bet365 in-play 无事件下的小幅漂移**（< 2c，无比分变化） | ❌ 不跟，噪声 | 这是 bet365 自己的库存调整/square 偏见，不是新信息。实证：纯噪声 60s 内够本移动只占 ~20% 且幅度小 |
| **临场前 pregame 8 家共识缓慢移动** | △ 另一回事 | 这是 pregame sharp money，是慢信号，不属于本套"事件延迟"打法。要做归 pregame 方向策略，不要混进事件套利 |

**判别核心：有没有对应的 Goalserve 比分/事件变化。** 有事件支撑的跳变 = 跟；没事件的漂移 = bet365 自己在动，不跟。代码里 `g_goal_freshness`（特征 #73）、`g_score_diff`（#0）就是这个闸口的原料。**没有事件闸口，这套必负期望**（小董 §结论）。

### 2.3 bet365 单源的偏见 — 必须扣掉的系统性误差

这是我的专业纠偏，前面提过，这里给操盘指引。bet365 是 square book，对公众偏好方向系统性偏价：

- 对**主队 / 热门 / over** → 系统性低赔（= de-vig 后公平概率**高估** 0.7-1.2pp）
- 对**客队 / 冷门 / under** → 系统性高赔（= 公平概率**低估**）

**操盘含义：** 当事件方向 = 公众偏好方向（主队进球 → 买主队 YES），bet365 跳到的新 fair **本身偏高**，我按它定 target_exit 会**高估收敛终点**，实际 PM 可能收敛不到那么高 → 我的 maker 出场单挂太高成交不了 → 撞 deadline 强平亏损。**对策：买公众偏好方向时，target_exit 在 bet365 fair 基础上回扣 0.7-1.2pp（book bias 修正）。** 买冷门方向时反之。这个 bias 修正应该作为特征喂模型（master-plan §0 哲学），但操盘手在 paper 期要盯着它校准。

### 2.4 冷门盘 vs 大联赛盘 — 可交易性天差地别

| 维度 | 大联赛盘（NBA/MLB/英超/ATP 大满贯） | 冷门盘（小联赛/低级别巡回赛） |
|---|---|---|
| PM 流动性 | 够（Tennis 大满贯 ±2tick $5-27k，NBA $124-4800 视 phase） | 极薄或没有 |
| bet365 in-play 覆盖 | 全 | 季节性缺、时段缺 |
| PM 重定价速度 | 中位 13.2s（够我们抢） | 可能根本不重定价（43.5% 无反应里多是这些） |
| **可交易性** | ✅ 甜区 | ❌ 流动性陷阱（§5） |

**铁律：只在大联赛盘做这套。** 冷门盘看着错价大（因为没人定价），但你吃不进（无深度）、出不来（无对手），错价是假的——它是"无流动性"的镜像，不是"信息优势"。**冷门盘的大 spread 不是机会，是警告。**

### 3.2 缺的 / 是约束的（必须正视）

| 缺口 | 现状 | 对打法的影响 | 归口 |
|---|---|---|---|
| **事件驱动触发路径** | paper_loop 仍 500ms 时间驱动轮询，无 score_change callback | **致命**：500ms tick 延迟吃掉本就薄的窗口，是兑现 12s 窗口的硬前提 | 工程，master-plan Phase 3（R-12 区，老郭+老韩 review） |
| **真双边对冲（开空）** | `position_controller` v1 只多侧，空头 clamp 0 | (c) delta 对冲做不了；只能做 (b) 单边 round-trip | M2，老韩 RM 签 |
| **in-play 多源 sharp 共识** | in-play 只有 bet365 单源（square book） | 锚的是 square 不是真 sharp，有方向偏见（§2.3） | **数据源天花板，无解** — Goalserve in-play 设计如此（老彭实证确认） |
| **Goalserve 2s 刷新 + 1s 轮询** | 感知延迟中位 ~1-3s，不是文档写的 1s | 占掉端到端 3.1s 里的大头，不可控 | 数据源天花板，除非升级合约 |
| **G2 可预测性证伪** | 还没用含真实进球的采集数据验"进球后 PM 是否够本收敛" | **整个方案的命门**，没验之前都是假设 | master-plan §7，需 AWS 含进球场次采集 |
| **bet365 book bias 实测校准** | 0.7-1.2pp 是行业历史数据，非本项目 notebook 实证 | target_exit 修正幅度待校准 | 老彭 paper 期校准 |

### 3.3 一句话信号盘点结论

**原料齐了，缺的是"事件触发管道"和"G2 证伪"。** 特征/fair 源/订单簿/执行核都在（master-plan §1 说"特征不用从零开始"，我核实属实）。真正卡住的是两件：① 工程上把 500ms 轮询改成事件触发（否则窗口吃不到）；② 用真实进球数据跑 G2 验证（否则方向都没证实）。**这两个不通，信号再全也是摆设。**

## §4 可交易性现实 — 哪些盘真能吃、流动性够不够、滑点吃不吃 edge

我们覆盖盘口的运动分布（老板给：网球 ~75% / 足球 / 篮球 / 棒球 / 电竞 / 板球）。逐个过可交易性。

### 4.1 流动性实测（`sport_profile.hpp` + 微结构实测）

±2tick 深度中位（USD），这是 size 天花板：

| 运动 | Pregame | Early | Mid | Late | 事件套利可交易性判断 |
|---|---|---|---|---|---|
| **Tennis（75%）** | $5000 | $21800 | $15000 | **$3000** | ✅ **最佳**。大满贯流动性意外厚（$10k 滑点仅 0.42c）。ace/break point 是离散事件，方向清晰。但 Late（决胜盘）深度掉到 $3k 要收 size |
| **Basketball** | $1500 | $4800 | $4500 | **$1200** | ✅ 好。每次得分是事件，Q4 hot（qhl 0.21s）冲击大但深度掉、qhl 极短 → 窗口更窄，要快 |
| **Baseball** | $1000 | $8900 | $5000 | **$1200** | ✅ 好。得分稀疏但冲击大；8+ 局 tie/1-run 是甜区（INPLAY_HOT），但 qhl 短 |
| **Soccer（足球）** | $500 | $300 | $250 | **$150** | △ **流动性薄**。进球是最强离散事件（冲击巨大），但 PM 深度只有几百刀 → 一次吃 $150-300 就到顶。spread 也宽（中位 8.8c）→ BE 高 |
| **Esports（电竞）** | $300 | $200 | $150 | **$100** | ❌ 流动性太薄 + base_fill 最低（0.35-0.55）。事件极快（objective/团战）但吃不进。**暂不做** |
| **板球（Cricket）** | 无 profile | — | — | — | ❓ `sport_profile` 表里没有板球（8 sport 是 Soccer/Basket/Tennis/Volley/AmFootball/Esports/Hockey/Baseball）。**需先确认 PM 是否覆盖 + Goalserve 是否有 in-play + 建 profile** |

### 4.2 滑点会不会吃掉 edge — 逐盘算账

关键不是"错价多大"，是"**错价 − BE − 滑点**还剩多少"。BE = 往返 fee + spread + 滑点（`arb_signal` 口径）。

| 运动 | 典型 spread | fee_rt（mid 0.5） | 进场滑点（$200 吃单） | BE 合计 | 典型事件错价 | **净 edge** |
|---|---|---|---|---|---|---|
| Tennis（深盘） | 1-3c | 1.5c | ~0.4c | ~3-5c | 4-8c（break） | **+1 到 +4c** ✅ |
| Basketball | 1c | 1.5c | ~0.5c（Late 更高） | ~3c | 3-6c（得分） | **+0 到 +3c** ✅ |
| Baseball | 1c | 1.5c | ~0.5c | ~3c | 大（得分稀疏冲击大） | **+正** ✅ |
| Soccer | 8.8c | 1.5c | 高（薄盘） | **~11c** | 进球冲击大（10c+）但 spread 吃掉 | **接近 0 或负** ⚠️ |
| Esports | 宽 | 1.5c | 很高（极薄） | 高 | — | **负** ❌ |

**操盘手结论：**
- **甜区 = Tennis + Basketball + Baseball 的极端价位盘**（mid<0.15 或 >0.85，BE 仅 1.7c，>BE 比例 9.3% 最高，小董 §B2）。这三个运动深度够、spread 窄、事件离散方向清。
- **Soccer 矛盾**：进球是最强事件（信息价值最高），但 PM 深度薄 + spread 宽（8.8c），BE 经常吃掉整个错价。**只在大联赛（英超/欧冠）+ 错价 > 12c 时做，size 限 $150-300。**
- **避开 near_half（0.35-0.65）所有运动**：BE 6.45c，>BE 仅 1.4%（小董），扣费负期望。**这是个反直觉但实证钉死的铁律——平盘看着机会多，其实最难赚。**
- **Esports / 板球暂不做**：前者流动性陷阱，后者连 profile 都没有。

### 4.3 网球占 75% 是好事 — 但要分阶段

我们覆盖最大的网球恰好流动性最好（大满贯 $5-27k）。事件套利在网球的形态：
- **可吃事件：** break point 转化（局分跳）、盘点（set point）、ace 连续（动量）。
- **fair 源：** `tennis_fair_value.hpp` 给了 totals/spreads 专属定价（games/sets 制），ML（moneyline）靠 bet365 in-play de-vig。
- **注意：** 网球 Late（决胜盘 set 3+）深度掉到 $3k、qhl 极短（500ms）→ 这恰恰是事件最密集（每个 break 都关键）但窗口最窄的时候。**决胜盘要么快进快出，要么不碰。**
- **风险：** 网球 in-play 价格本身波动剧烈（一个 break 就能从 0.4 跳到 0.7），反向事件（立刻被 break back）很常见 → §1.5 的"反向事件立即平"在网球尤其重要。

## §5 操盘手红线 / 经验教训 — 这套打法最容易死在哪

带血的经验。每条配规避建议。

### 5.1 死法一：被反向选择（adverse selection）— 最致命

**怎么死：** 我以为我快（抢在散户前），其实有人比我更快、或者那个"过时挂单"根本不是过时的——是对方做市商**故意挂的诱饵**（他已经知道事件、故意留个旧价单引我吃，吃完他反向收割）。我吃完发现价格不往我以为的方向走。

**为什么这套尤其危险：** 我们锚 bet365 单源，bet365 自己可能慢、可能错。如果 PM 上有比 bet365 更快的信息源（有人在场内看直播、有人接 Sportradar 官方源），我吃的"过时单"其实是聪明钱的反向单。

**规避：**
- `adverse_selection_score`（fill_rate_model 已有）> 0.5 → -0.20 penalty，AS 高直接不进。
- **看 trade flow**：如果我要买 YES，但 `buy_ratio` 已经 > 0.7（散户已经在猛买了），说明重定价已经在走，我晚了，**别追**。错价是给"第一个发现的人"的，不是给"最后一个"的。
- **只吃 56.5% 有反应的盘**：43.5% 无重定价的盘里，相当部分是"PM 比 bet365 更早知道所以早就定价了"——我去吃 = 当接盘侠。

### 5.2 死法二：库存爆（inventory blow-up）

**怎么死：** 连续事件不断进场（NBA 末节 30s 连续得分），仓位越堆越大；某次没收敛、撞 deadline 强平、又来反向事件，几个亏损叠加；或者预测源断流时手里一堆裸方向仓。

**规避（§1.5 已展开）：** 必平时限强平 + 断流清仓 + 单场球 cap + 总在途敞口 cap。`master-plan §4` 的 open-leg fail-safe 是硬兜底，**不可删**（删了 = 把灾难防护交给未验证的模型）。

### 5.3 死法三：追价（chasing）

**怎么死：** 进场时 ask 0.72，我想吃 $500，但 0.72 只有 $180，我一路追吃到 0.76——结果均价 0.74，离新 fair 0.78 只剩 4c，扣 BE 2.7c 净 edge 1.3c，滑点又吃掉，白干甚至亏。

**规避：** `position_controller` 的 reservation 范式已经对——**限价绝不追价，越过临界价就不买**。操盘手补：**进场吃单设硬上限价**（吃到离新 fair 还剩 cushion 就停），剩余 size 宁可不要也不追。**"吃不满"比"追贵了"好一万倍。** size 不够是流动性的错，不是我的错；追价亏是我的错。

### 5.4 死法四：冷门盘流动性陷阱（§4.2 已警告）

**怎么死：** 看到冷门盘错价 15c，兴奋进场，发现 ask 只有 $30 深度，吃进去后想平仓——没有对手盘，挂 maker 单挂一天没人接，撞 deadline 市价平——市价那边也没深度，滑点 10c，倒亏。

**规避：** **进场前必查出场深度（exit_depth）。** `arb_signal` 已有 `exit_depth_usdc`（L1-L5 累计），`master-plan §4` 明确 "EXIT_DEPTH 检查：进得去出不来是套利第一杀手"。操盘手铁律：**进场 notional ≤ 出场深度的一半。** 只做大联赛盘（§2.4）。

### 5.5 死法五：把"事件套利"做成"方向赌博"

**怎么死：** 错价窗口过了没平掉，舍不得割，想"反正主队领先，等结算"——这就从套利退化成押结算。一旦比赛反转，亏的是整个仓位不是错价。

**规避：** 时限到了**无条件平**，哪怕"看起来还会涨"。我们不是预测家（§0），不赌结算。**纪律 > PnL（公司铁律）。**

### 5.6 死法六：bet365 偏见误导 target（§2.3 已展开）

买公众偏好方向时，bet365 fair 偏高，target_exit 挂太高成交不了 → 撞 deadline 强平。**规避：book bias 修正喂模型 + paper 期校准。**

### 5.7 死法七：忽略 G2 命门就上规模

**怎么死：** 急着上量，没用真实进球数据验"进球后 PM 真的朝可预测方向够本收敛"，结果 paper 跑下来负期望，才发现 12s 滞后是真但够本移动太稀（2.9%）、扣费后不够。

**规避：** **G2 不过，不上热路径**（master-plan §5 Phase 0 命门）。先用含真实进球的 AWS 采集数据离线验，go/no-go 进 MEETINGS。这是整个方案的第一个、也是唯一能证伪的里程碑。

## §8 一页纸结论（给老板）

1. **方案成立，但本质是"事件延迟错价"不是"价格预测"。** 别做连续预测（实证负期望），要做事件闸口触发。
2. **它是补充策略不是主引擎。** 日 $5-50 量级，天花板是流动性+覆盖率不是模型精度。
3. **执行核已经对了**（arb_signal 的 taker进/maker出/BE门/深度门 + position_controller 的限价不追价）。缺的是事件触发管道 + 开空（真双边）。
4. **甜区 = Tennis/NBA/MLB 极端价位盘。** 禁 near_half、禁冷门、禁 Esports。Soccer 只在大联赛+大错价小 size。
5. **认知纠偏：in-play 锚的是 bet365 单家 square book，不是 sharp 共识。** 抢的是速度优势不是聪明优势，要扣 book bias。
6. **命门是 G2。** 没用真实进球数据证实"够本收敛"之前，不上热路径。
7. **七个死法**（反向选择/库存爆/追价/流动性陷阱/退化成赌博/bet365 偏见/跳过 G2）都有现成护栏（AS penalty / fail-safe / reservation / exit_depth / 时限强平），**护栏不可删**。
