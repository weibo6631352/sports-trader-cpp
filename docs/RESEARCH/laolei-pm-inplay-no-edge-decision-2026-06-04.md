**在 Polymarket in-play 传统体育上，我们当前体质（数据慢 2.3s、bet365 直采被封、无信息/速度优势）没有任何已验证的 alpha。三条盈利路径全部被数据证伪。** 不是参数/引擎/资金问题，是赛道与体质不匹配。

## 3. 唯一未被证伪、且不依赖"速度"的 odds-edge 角度: 赛前 CLV

我们测的全是 **in-play(实时)**, 那恰是我们最弱的地方(慢数据)。**赛前(pregame)是慢变量, 速度劣势不咬人。**

- **赛前 CLV(closing line value):** 经典体育博彩 edge —— sharp(bet365)收盘线对结果的预测力强于散户盘。若 PM 赛前价 vs bet365 de-vig fair 有系统性 gap, 且 PM 价随临场**收敛**到 sharp 线 → 在 gap 处建仓, 吃**收敛**(动态, 非结算, 符合老板「动态持仓」)。
- **不需要速度**(赛前线动以小时计) → 绕开我们的死穴。
- **风险/前提:** 需验证 PM 赛前是否真低效(存在持久 gap) —— [[poly-arb-theses-results]]/[[only-yes-pregame-ml]] 有负面先验(PM 整体高效), 但未在"赛前 sharp gap 收敛"这个具体角度上实测过。
- **验证法(慢但正确):** 系统记录(赛前 PM 价, bet365 fair, 临场/结算 outcome)逐事件 → 看 gap 是否预测收敛方向。需数天数据。

## 4. 战略选项 (待拍)

- **A. 验证赛前 CLV** —— 唯一存活的 odds-edge 角度。改系统采集赛前 PM-vs-bet365 gap + 收敛, 数天出数。若有 gap 收敛 → 找到 edge; 若也高效 → PM 整体无我们的份。
- **B. 换赛道找真优势** —— 要么真低延迟数据(bet365 直采: 住宅 IP + 反检测, 工程+灰色 ToS), 要么去更低效的市场(冷门/PM 外), 要么做需要真模型 alpha 的事。
- **C. 接受 PM 不是我们能赢的场** —— 复盘体质(我们的真实优势是什么? C++ 工程力? 那该用在哪?)。

**复用资产(非沉没):** 数据管道 / paper 引擎 / RM / 前端 / 延迟+lead-lag 测量栈 —— 找到任何新 edge 都能直接复用。
