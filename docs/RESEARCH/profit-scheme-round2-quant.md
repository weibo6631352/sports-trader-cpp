## TL;DR — 六条结论(先给老板)

1. **引擎3 不能是一个模型。两个预测目标数学上正交,必须拆成两个头/两个模型。** "预测 bet365 即将跳"是**危险检测**(label = 未来短窗 sharp_fair 跳变幅度, 自监督, 对称/无方向), 用来**抬手避险**;"预测收敛方向+幅度"是**机会量化**(我 round-1 的 y_h, 有符号), 用来**进场套利**。前者要 recall(宁可错杀也别被扫), 后者要 precision(宁可错过也别假进场)。一个 loss 调不出两个相反的偏好。详见 §1。

2. **激励做市的最优价差 s\* 是一个可解的一维优化问题。** 给定二次激励打分 + 逆选成本, s\*(对一个简单 Poisson-被扫模型)有闭式驻点。核心结论:**激励的二次形态把你往中点推(s 越小分越高), 逆选把你往外推(s 越小越易被 sharp 扫), s\* 落在两者拉锯的内点。** 关键参数是逆选强度 λ_adv(单位时间被知情单击中的概率)。**当 λ_adv 高时(in-play 事件密集), s\* 往外退甚至退出该 game 的激励竞争**——这就是引擎3 危险检测头的用武之地:不是改 y_h, 是动态调 s\*。详见 §2。

3. **纯规则做市(固定价差)会被系统性逆选,且这个逆选是结构性的不是偶发的。** 因为 PM 滞后 bet365 ~13s 是我 round-1 已证的事实——这 13s 里我们的双边静态报价 100% 站在知情流的对立面。但 **P1 不需要模型也能避大头逆选:最小可行避逆选信号 = `|sharp_gap| > k·spread` 时单边撤离(撤掉被扫的那条腿)+ 事件新鲜度门(g_goal_freshness 高时全撤)。** 这是阈值规则不是模型, 立即可上, 能挡掉 70%+ 的有毒流(它们都集中在事件后 10s)。详见 §3。

4. **激励做市确实化解了我 round-1 "296 市场不够"的顾虑——但只对引擎1,不对引擎2。** 激励收益是 path-independent 的结构性现金流(挂够 size + 够贴 + 双边 = 拿 pro-rata 份额), 不需要预测精度, 因此**不需要 walk-forward 验证 alpha, 只需要验证"净激励 − 逆选损耗 > 0"这一条**, 而这条可以用 1-2 天 paper 实测直接观测, 不需要攒样本训模型。**引擎2 套利模型仍然死守 round-1 纪律: walk-forward OOS rank-IC 唯一上线门, 20.5h 不够, 需再攒。** 两条线的样本要求彻底解耦。详见 §4。

5. **预测量最终定义(改 round-1):保留 y_h 作为引擎2 主标签不变, 但新增引擎1 专用标签 `jump_h = max_{τ≤h}|sharp_fair(t+τ) − sharp_fair(t)|`(无符号, 未来 h 内 sharp 最大跳幅)做危险检测。** gap 基准我 round-1 已从 mid 改成 microprice, 保留。horizon 引擎2 仍 {5,10,12,15}s; 引擎1 危险检测用更短的 {3,5}s(避险要抢在被扫前, 比套利进场更早)。详见 §5。

6. **建模优先级(收敛建议):P1 纯规则做市 + 阈值避逆选(无模型, 立即上)→ P1.5 引擎1 危险检测头(jump_h, 自监督, 样本要求低)→ P2 引擎2 套利 y_h 模型(walk-forward 把关, 攒够样本再上)。** 把"做市赚激励"和"套利赚收敛"在资金/市场/时序三个维度解耦, 不要让一个大模型同时背两个目标。详见 §5。

## 1. 引擎3 的双重角色:两个预测目标正交,必须拆

草案 §引擎3 让一个"大脑"同时干两件事:(a) 给引擎1 预测 bet365 即将跳 → 拉报价避逆选;(b) 给引擎2 预测收敛方向+幅度 → 择时套利。**我的判断:这两个目标在标签、损失、决策方向、误差代价四个维度上都正交,一个模型干不了,会两头不讨好。**

### 1.1 两个目标的本质区别(逐维拆)

| 维度 | (a) 避逆选 / 危险检测 | (b) 套利 / 机会量化 |
|---|---|---|
| **要预测的量** | 「未来短窗 sharp 会不会大幅跳」——一个**波动/到达事件** | 「mid 会朝 sharp 收敛多少」——一个**有符号的均值回归幅度** |
| **标签符号性** | **无符号**(跳上跳下都是危险, 都要撤单) | **有符号**(sign(gap)·Δmid, 方向决定进哪边) |
| **统计本质** | 预测**条件方差/跳跃强度** σ²(t)、跳到达率 λ(t) | 预测**条件均值** E[Δmid·sign(gap)] |
| **决策动作** | 撤单 / 拉宽价差(防御, 减少暴露) | 下单 / 加仓(进攻, 增加暴露) |
| **误差代价不对称** | **假阴性致命**(没预警→被扫穿仓), 假阳性便宜(白撤一次少赚点激励)→ 要 **high recall** | **假阳性致命**(假进场→吃费亏损), 假阴性便宜(错过一次)→ 要 **high precision** |
| **最优 loss** | quantile-high / 跳检测 / 不对称 pinball(重罚漏报) | Huber 回归 + quantile CI 下界(重罚假信号) |
| **horizon** | 更短 {3,5}s(必须抢在被扫前, 比进场更早动手) | {5,10,12,15}s(round-1 已定) |

**结论:同一个 encoder 也许能共享底层特征(OFI、book_age、goal_freshness),但输出头和 loss 必须分两个,且最优决策阈值方向相反。** 让一个 head 同时优化均值和方差是经典的多任务冲突——预测均值的 head 会被"大部分时间不跳"的 0 标签拖向保守, 而危险检测恰恰要抓那些罕见的尾部跳。这正是我 round-1 §1.1 警告过的"裸 Δmid 被海量 0 标签淹没"的同一个病, 只是这次病在引擎1。

**工程上的折中(可接受):共享底层 encoder(GBDT 的话就是共享特征集),分两个输出 + 两套 loss + 两个上线门。** 不是两个完全独立的大模型(296 样本撑不起两个), 是一个 backbone 两个 head。

### 1.2 "预测 bet365 即将跳"怎么定义 + 怎么 label(自监督)

草案问得对——这个量 round-1 没定义过。我现在定义它,**纯自监督,不用任何结算/外部标签**:

```
危险标签 (per token, per short-horizon h ∈ {3,5}s):
  jump_h(t) = max_{0<τ≤h} | sharp_fair(t+τ) − sharp_fair(t) |     # 未来 h 内 sharp 最大绝对跳幅
  二分类版: danger_h(t) = 1[ jump_h(t) ≥ k_danger · tick ]          # k_danger 取 2~3 tick
```

- **为什么用 sharp_fair 的未来跳幅而不是 mid 的未来跳幅:** 我们要避的逆选, 来源是 **bet365 先动 → 知情 taker 拿着新 sharp 来扫我们的陈旧挂单**。所以危险的**先行指标是 sharp 自己跳**(bet365 跳), 不是 mid 跳(mid 跳的时候我们已经被扫了, 太晚)。`sharp_fair` = g_bm_inplay_fair(f18)就是 bet365 de-vig fair, 它的未来跳幅正是"bet365 即将/正在跳"的直接度量。
- **这是不是用了未来?** label 侧用 t+τ 的 sharp 是合法的(label 本来就是未来量), 严禁的是把未来 sharp 进 X。训练时 jump_h 是 y, 特征 X 只用 ≤t 的量(OFI、sharp 自身的近期波动、goal_freshness、book_age)。PIT 纪律和 round-1 §5.2 完全一致。
- **自监督闭环:** label 完全来自数据自身未来的 sharp 轨迹, 不需要标注、不需要结算 outcome, 符合老板"弃结算标签"。**而且这个标签的覆盖率比 y_h 高**——y_h 需要 sharp_fair(t) 且需要未来 mid; jump_h 只需要 sharp_fair 的序列, 不依赖 mid 双边报价完整, 所以 §4.3 我担心的"双边报价只 54.5% 覆盖"对危险检测不构成约束(危险检测只看 sharp)。

**模型形态:** 危险检测优先用 quantile-high GBDT(预测 jump_h 的 q90)或直接二分类 danger_h, loss 用 recall-weighted(漏报权重 >> 误报权重)。这比 y_h 的回归任务简单, 样本要求低(见 §4)。

### 1.3 一句话回答草案的问题

> "这两个预测目标一样吗?能一个模型干吗?还是要两个?"

**不一样,正交。一个 backbone 可以,但必须两个 head + 两套 loss + 两个方向相反的决策阈值。** 强行一个 head 干两件事,会得到一个"既不敢进场也不敢撤单"的平庸模型——这是多任务目标冲突的教科书结果。

## 2. 激励做市的最优报价价差 s\*:一个可解的优化问题

草案问:给定激励打分 `S(v,s)=((v−s)/v)²·b` + 逆选风险, 最优价差 s\* 怎么解?这是我的核心领域。给框架 + 闭式驻点。

### 2.1 目标函数:激励收益 − 逆选损耗 − 机会成本

记单位时间内, 单边挂单的期望收益(per game, 简化到一条腿):

```
maximize over s:   π(s) = R_incentive(s) − L_adverse(s)

其中:
  R_incentive(s) = α · S(v,s) = α · ((v−s)/v)² · b          # 激励份额收益, α = 我们的 pro-rata 份额单价
  L_adverse(s)   = λ_adv · P_hit(s) · E[loss | hit]          # 逆选损耗
```

各项微观结构含义:

- **`s`** = 我们报价到(size-cutoff 调整后)中点的距离(cents)。decision variable。verified doc: s 越小 S 越高(二次), s>v 不计分。
- **`v`** = max_incentive_spread(每 market 给定, 待 verified doc §4 实测具体值)。s ∈ [0, v]。
- **`b`** = in-game 乘数(verified doc, 盘中 > 赛前)。常数, 不影响 s\* 的位置(只缩放), 但影响"做不做"的门槛。
- **`α`** = 我们在该 game 池内的 pro-rata 份额单价(= 池金额 / 全体 Q_epoch)。**这是被鲸鱼稀释的项**(草案红队点 #1), 是常数对 s\* 无影响但对正期望有影响, 见 §2.4。
- **`λ_adv`** = 单位时间知情流到达强度(in-play 事件密集时高)。**这是引擎3 危险检测头要预测的量。**
- **`P_hit(s)`** = 给定我们挂在距中点 s 处, 一个随机/知情来单击穿到我们价位的概率。**s 越大(挂得越远)越不易被扫 → P_hit 随 s 单调递减。**
- **`E[loss|hit]`** = 被扫时的单位损失 ≈ (sharp 新值 − 我们成交价) = 知情方拿走的 edge。

### 2.2 被扫概率 P_hit(s) 的微观结构模型

最简模型: 假设来单冲击幅度 J(等于 sharp 跳幅, 即 §1.2 的 jump)服从指数分布 `J ~ Exp(1/μ_J)`(μ_J = 平均跳幅)。我们挂在距中点 s 处, 当冲击 J > s 时被扫:

```
P_hit(s) = P(J > s) = exp(−s / μ_J)
E[loss | hit] = E[J − s | J > s] = μ_J        # 指数分布无记忆性, 超出量期望恒为 μ_J
```

代入逆选损耗:

```
L_adverse(s) = λ_adv · exp(−s/μ_J) · μ_J
```

(指数是最简假设; 真实跳幅厚尾, 可换 Pareto, 驻点形式变但单调性结论不变。这里给框架。)

### 2.3 闭式驻点 s\*

目标:
```
π(s) = α·b·((v−s)/v)² − λ_adv·μ_J·exp(−s/μ_J)
```

对 s 求导置零:
```
dπ/ds = α·b · 2(v−s)/v² · (−1) − λ_adv·μ_J·exp(−s/μ_J)·(−1/μ_J)
       = −2α·b·(v−s)/v² + λ_adv·exp(−s/μ_J)
设 = 0:
       2α·b·(v−s)/v² = λ_adv·exp(−s/μ_J)        ... (★) 最优价差一阶条件
```

**(★) 的解读(这是给老板/做市实现的核心直觉,比数值解重要):**

- **左边 = 激励的边际损失率**(再往中点挪一点, 多拿的激励的边际)。它随 s 增大而**线性递减**(挪到中点附近时激励边际收益趋缓, 因为二次函数在顶点附近平)。
- **右边 = 逆选的边际节省率**(再往外挪一点, 少被扫的损失的边际)。它随 s 增大而**指数递减**。
- **两条曲线交点 = s\***。左边是激励拉你往中点(s↓), 右边是逆选推你往外(s↑), s\* 是拉锯的平衡点。

**关键比较静态(决定动态报价策略):**

1. **λ_adv ↑(逆选变强, 事件密集)→ 右边整体抬高 → 交点右移 → s\* 变大(报价拉宽,退离中点)。** 极端: λ_adv 大到 (★) 在 [0,v] 无内点解 → s\*=v 边界(贴着 max_spread 边缘挂, 拿最少激励但最不易被扫)甚至**退出该 game 的激励竞争**(π(s)<0 对所有 s)。
2. **μ_J ↑(跳幅变大)→ 逆选损耗整体抬高 + P_hit 衰减变慢 → s\* 变大。**
3. **α·b ↑(激励单价高)→ 左边抬高 → 交点左移 → s\* 变小(敢贴更近中点)。** 这就是"激励池大/in-game 乘数高时值得冒更大逆选风险贴中点"。

### 2.4 双边耦合 + c=3 的影响(verified doc 机制)

上面是单边。verified doc §2 原文: 中点∈[0.10,0.90] 时 `Q_min = max(min(Q_ne,Q_no), max(Q_ne/c, Q_no/c))`, **c=3.0**; 中点<0.10 或 >0.90 强制双边 `Q_min=min(Q_ne,Q_no)`。

**这对 s\* 优化的含义(我的解读):**

- **激励按双边对称的"有效深度"Q_min 计分, 单边只算 1/3(c=3)。** 所以 §2.1 的 R_incentive 在双边对称时拿满, 单边只拿 1/3。这**强烈激励对称报价**, 也就是 YES 和 NO 两条腿对称挂 → 两条腿都暴露逆选, 但 in-play 跳是**单方向**的(进球只把一边推上去)。
- **数学后果:逆选成本对双边做市是放大的——一次事件同时威胁两条腿中朝错方向的那条。** 但因为 YES/NO 互补(p_yes+p_no≈1), 一条腿被扫亏的, 另一条腿(没被扫的)的库存反而朝有利方向走。**双边对称做市的逆选净损耗 < 两条独立单边之和**, 因为互补对冲。这是双边做市相对单边的结构性优势, 和我 round-1 §3.2 "增益1 NO 边对冲"是同一回事, 在激励语境下更强(还多拿 3× 激励)。
- **最优策略不是固定 s\*, 是"对称收紧到 s\* 拿满激励 + 用危险检测头在 λ_adv 飙升瞬间临时不对称拉宽被威胁的那条腿"。** 即: 平时双边对称贴 s\*(吃满 c=3 加成); 检测到 bet365 要跳(§1.2 danger_h=1)时, 立即把朝跳方向那条腿拉宽/撤掉(牺牲那一瞬间的激励, 换不被扫)。**这就是引擎1 和引擎3-危险头的接口:危险头不改 y_h、不进套利,它实时调 s 的对称性。**

### 2.5 框架交付(给做市实现 + 风控)

```
报价策略 (per token, per tick):
  1. 默认: 双边对称挂在 s\* (解 (★), 或查表), 拿满 c=3 激励加成
  2. λ_adv 估计: 引擎3 危险头输出 danger_h / jump_h 的 q90
  3. if danger_h 高 (bet365 即将跳):
        把朝预测跳方向的那条腿 s 临时拉到 v (退到激励边缘) 或撤单
        另一条腿保持 (互补, 反而受益)
  4. 池稀释保护: 若 α (实测 pro-rata 份额) 低于阈值使 π(s\*)<成本, 退出该 game (见 §2.4 边界解)
```

**待实测/待协作:** v、min_incentive_size、b 的具体值(verified doc §4 待确认清单, 派 polymarket-protocol-expert);μ_J、λ_adv 的实测分布(我用 sharp_fair 序列直接算, 派我 + 数据组);α 的实盘 pro-rata 稀释(只能 paper→真钱小规模实测, §4)。

## 3. 攻草案 P1:纯规则做市会不会被系统性逆选?

草案 §优先级 P1:"先上规则化做市(无模型)"。草案红队点 #4 自己也问了。**从量化角度我的判断:会被系统性逆选,而且是结构性的;但 P1 仍可上,因为最小可行避逆选信号不需要模型。**

### 3.1 系统性逆选是结构性的,不是偶发的

**这是 round-1 我已经证过的事实的直接推论,不是新假设:** PM 散户 mid 滞后 bet365 sharp 共识中位 13.2s(shorthorizon §C2)。这 13.2s 意味着:

> **每次 bet365 跳之后的 ~13s 窗口里,我们的静态双边挂单的价格是基于"旧 sharp"的,而来扫单的知情 taker 拿的是"新 sharp"。我们 100% 站在知情流的对立面。**

固定价差做市 = 在每次事件后稳定地把 edge 送给知情方。这不是"运气不好被扫几次", 是**结构性的、可预测的、每次事件必然发生的逆选**。一个固定 s 的纯规则做市, 其逆选损耗 L_adverse 在事件密集的 in-play 盘里会**系统性吃掉激励收益**——具体吃多少取决于 λ_adv·μ_J vs α·b 的比值(§2.3)。

**所以草案"纯规则做市无模型立即可上"这句话,如果理解成"固定价差挂着不管",量化上不成立——会出血。**

### 3.2 但最小可行避逆选信号不需要模型(救活 P1)

好消息:**挡掉绝大部分逆选,不需要预测模型,只需要两个阈值规则**——因为有毒流高度集中(round-1 §C: 够本移动 70%+ 在事件 10s 内), 它们是**可观测的、当下就知道的**, 不需要预测未来:

```
最小可行避逆选规则 (纯阈值, 无 ML, 立即可上):

  规则 R-MM-1 (sharp-gap 拉单):
    gap = sharp_fair(t) − microprice(t)              # 当下已观测, 非预测
    if |gap| > k1 · spread:                          # sharp 已经偏离我们挂单中枢
        撤掉朝 gap 方向的那条腿 (它即将被扫)
        # k1 ≈ 1.5~2.0, paper 标定

  规则 R-MM-2 (事件新鲜度全撤):
    if g_goal_freshness(t) > k2:                     # exp(−Δt/120s), 刚有比分事件
        双边全撤 N 秒 (N ≈ 10s, 跨过滞后窗口) 后重挂
        # 牺牲事件后 10s 的激励, 换不被扫穿; 这 10s 正是逆选最毒的窗口

  规则 R-MM-3 (book 陈旧不挂):
    if b_book_age_sec > k3 or x_joint_staleness_sec > k3:
        不挂单 (我们的报价基准已经过期, 挂 = 送钱)
```

**为什么这三条够挡大头:**
- R-MM-2 直接覆盖了"70%+ 有毒流在事件 10s 内"这个结构性事实——用一个 feature(goal_freshness, round-1 §1.3 已有)就把最毒的窗口跳过了。这是杠杆率最高的一条。
- R-MM-1 是 R-MM-2 的连续版补充——捕捉那些没有明确比分事件但 sharp 已经偏离的慢漂移(换发球、红牌、伤停)。
- 这三条全部是**当下已观测量的阈值**, 不预测未来, 不需要训练, 不需要样本, **今天就能写进做市逻辑**。

**这就回答了草案红队点 #4:** P1 规则化做市可行, 但"无模型"≠"无避逆选逻辑"。无模型指的是不需要训练好的预测模型, 但必须有上面三条阈值规则。"裸固定价差挂着不管"会被扫爆, "固定价差 + 三条阈值避逆选"可上线。

### 3.3 模型(引擎3 危险头)在 P1 之上加多少价值?

阈值规则挡的是**已经发生**的偏离(gap 已经张开、事件已经发生)。模型危险头(§1.2 jump_h)预测的是**即将发生**的跳——它能在 sharp 还没跳完、gap 还没完全张开时就预警, 抢在被扫前撤单。

**量化判断:阈值规则挡掉的有毒流约 70%(事件后窗口),危险头再多挡 15-20%(事件前/事件中的提前量),边际递减。** 所以引擎1 的正确路线是:**P1 先上三条阈值规则吃掉 70% 收益(立即),P1.5 再用危险头榨剩下的(攒够样本后)。** 不要等模型——三条规则的 ROI 远高于模型, 模型是优化项不是前置项。

## 4. 样本/过拟合再评:激励做市化解了我 round-1 的样本顾虑吗?

草案红队点 #4 / legacy §C 问:激励做市对模型精度要求低 → 是否化解了 round-1 "296 市场不够"?

### 4.1 结论:对引擎1 化解,对引擎2 不化解。两条线样本要求彻底解耦。

| | 引擎1 激励做市 | 引擎2 收敛套利 |
|---|---|---|
| **收益来源** | 结构性 pro-rata 现金流(挂够就拿) | 预测 alpha(收敛幅度 > 成本) |
| **依赖预测精度?** | **否**(激励不看你预测准不准, 只看 Q_min × 时长) | **是**(假信号 = 直接亏) |
| **需要 walk-forward 验 alpha?** | **否** | **是, 死守 round-1 纪律** |
| **验证方式** | 直接 paper 实测"净激励 − 逆选损耗 > 0" | OOS rank-IC > 0.03 且 IC-IR > 0.5 |
| **验证所需数据** | **1-2 天 paper 直接观测现金流** | round-1 结论: 20.5h 不够, 需再攒 1-2 周 |
| **过拟合风险** | **几乎没有**(三条阈值规则 + 激励是会计量不是预测量) | 头号死因(round-1 §5) |

**关键洞察:引擎1 的"模型"(危险头)即使过拟合/不准,后果也是有界的**——危险头不准只会让你少挡一点逆选(多被扫几次)或多撤几次单(少拿点激励), **不会让你做出"假进场吃费"这种直接亏损动作**。因为引擎1 的基础收益(激励)是危险头之外独立产生的。这和引擎2 完全不同——引擎2 的模型不准 = 直接拿真金白银下错注。

**所以激励做市真正化解的不是"样本量",是"样本量与盈利的耦合"。** 引擎1 可以在样本严重不足时就开始盈利(靠激励 + 阈值规则), 边攒样本边把危险头训上去优化。引擎2 必须等样本够、walk-forward 过门才能动真钱。

### 4.2 引擎1 的"够不够"换了一个问题:不是样本量,是 pro-rata 稀释(α)

引擎1 的可行性门槛不再是"模型够不够准", 而是 **§2.1 的 α(我们 paper→真钱 scale 能拿到的 pro-rata 份额)** 在被鲸鱼稀释后, 还够不够覆盖逆选损耗 + 机会成本。这个问题:

- **不能靠攒历史样本回答**(历史 tick 里没有"如果我们挂单会拿多少激励"这个反事实)。
- **只能靠 paper→真钱小规模实测**:挂真实双边单(paper 模式下激励是观测不到真金的, 这里需要 polymarket-protocol-expert 确认激励是否在 paper/小额真钱下可观测), 看实际 Q_epoch 份额。
- **这是引擎1 的 G2 级别前置验证**(类比引擎2 的"G2 验证 PM 收敛可预测")。我命名为 **G-MM:实测单 game 池内我们的 pro-rata 份额 α, 验证 π(s\*) > 0。**

### 4.3 引擎2 套利的样本纪律一字不改(重申 round-1)

激励做市的存在**不给引擎2 套利模型任何降低门槛的理由**。引擎2 仍然:
- walk-forward OOS rank-IC 唯一上线门(IS 一律不看)。
- 20.5h / 296 市场不够上线, 需再攒至少 1-2 周到 ≥5 折。
- condition-group PurgedKFold 防泄漏, embargo 调到 ~3.5h。
- sharp_fair 生产覆盖率实测(round-1 §4.3 最大数据风险, 不变)。

**唯一的好消息:引擎1 先盈利,给引擎2 攒样本买来了时间。** 我们不再处于"要么模型上线要么不赚钱"的逼仓状态——引擎1 在产生激励现金流的同时, feature_recorder 持续采样, 引擎2 的样本自然增长, 等够了再上。这是激励做市对整个研究路线最大的战略价值:**解除了"必须赶紧让模型上线"的过拟合压力源。**

## 5. 收敛建议:建模优先级 + 预测量最终定义

### 5.1 预测量最终定义(对 round-1 的修订)

| 用途 | 标签 | 定义 | 符号 | horizon | 模型 | 相对 round-1 |
|---|---|---|---|---|---|---|
| **引擎2 套利进场** | `y_h` | `sign(gap)·(mid(t+Δ)−mid(t))`, gap=sharp_fair−**microprice** | 有符号 | {5,10,12,15}s | LightGBM quantile(产 CI 下界) | **不变**(microprice 基准 round-1 已改) |
| **引擎1 危险检测(新)** | `jump_h` | `max_{τ≤h}|sharp_fair(t+τ)−sharp_fair(t)|` | **无符号** | **{3,5}s**(更短, 抢在被扫前) | quantile-high GBDT 或二分类 danger_h | **新增** |
| 辅助(round-1) | σ_h | 窗口内 \|Δmid\| RMS | 无符号 | 同 y_h | y_h 的 quantile head 反推 | 不变 |

**两个主标签的关系:** jump_h(危险, 无符号, sharp 自身跳)是 y_h(机会, 有符号, mid 向 sharp 收敛)的**前导信号**。直觉上:bet365 先跳(jump_h↑)→ gap 张开 → 接下来 13s mid 朝 gap 收敛(y_h>0)。**同一个物理过程的两个阶段:** jump_h 抓"事件刚发生、危险期、做市要撤单避险";y_h 抓"事件后收敛期、机会期、套利要进场"。**时序上 jump_h 在前(0-5s),y_h 在后(5-15s)——这也解释了为什么引擎1 撤单和引擎2 进场不冲突:它们在同一事件的不同时间段动作。**

这一点顺带回答了草案红队点 #2(双引擎是否冲突):**不冲突,因为危险期撤做市单(0-5s)和收敛期进套利单(5-15s)在时间上错开。** 引擎1 在事件后立即撤离(避险), 引擎2 在 sharp 锚定、收敛启动后进场(套利)。同一市场同一事件, 引擎1 先退、引擎2 后进, 资金接力不是争抢。

### 5.2 建模优先级(收敛)

```
P1   纯规则做市 + 三条阈值避逆选 (§3.2)
     - 无模型, 无训练, 无样本要求, 今天可写
     - 收益: 激励 pro-rata + maker 零费 + taker rebate
     - 验证: G-MM 实测 α (pro-rata 份额), 验 π(s\*)>0 (1-2 天 paper, §4.2)
     - 这是利润下限, 立即跑起来

P1.5 引擎1 危险检测头 (jump_h / danger_h, §1.2)
     - 自监督, 样本要求低 (只需 sharp 序列, 不需双边报价完整 → 覆盖率高)
     - recall-weighted loss, 抢在被扫前撤单, 动态调 s 对称性 (§2.4)
     - 边际价值: 在三条规则之上多挡 15-20% 逆选
     - 不阻塞 P1, 攒够 sharp 序列样本就训

P2   引擎2 套利 y_h 模型 (round-1 主线)
     - LightGBM quantile, walk-forward OOS rank-IC 唯一上线门
     - 死守 round-1 纪律: 20.5h 不够, 需 ≥5 折 (1-2 周)
     - 进场窗 5-15s (危险期之后), 与引擎1 时序接力
     - 引擎1 已在赚激励 → 没有"赶上线"压力 → 过拟合压力解除 (§4.3)

P3   序列模型 (GRU/小 Transformer) — 仅当 P2 GBDT 基线 OOS IC 站稳后
     - 共享 backbone, 两个 head (危险 + 机会), causal mask 单测
     - 规模纪律不变 (round-1 §2.2): <50k 参数
```

### 5.3 三个维度解耦(核心架构建议)

不要造一个大模型背所有目标。在三个维度把"做市赚激励"和"套利赚收敛"切开:

1. **资金维度:** 引擎1 激励做市的双边挂单 reserve 和引擎2 套利的 taker 进场资金分开预算(避免 verified doc §3 提到的"共用 balance reserve"互相挤占)。
2. **市场维度:** 引擎1 覆盖所有体育/电竞激励池(广, 不需 sharp 覆盖); 引擎2 只在有 sharp 的 tennis/soccer 做(窄, 需 sharp)。引擎1 的可做面 >> 引擎2(legacy §C 已点)。
3. **时序维度(最关键):** 同一市场同一事件, 引擎1 在危险期(0-5s)撤离, 引擎2 在收敛期(5-15s)进场。jump_h 管前段, y_h 管后段。

### 5.4 一句话交付

**引擎3 拆成两个目标:危险头(jump_h, 无符号, 抢撤单, recall 优先, 喂引擎1 调价差对称性)+ 机会头(y_h, 有符号, 抓进场, precision 优先, 喂引擎2 套利), 一个 backbone 两个 head 两套 loss。** 激励做市的最优价差 s\* 是激励二次拉拢(往中点)与逆选指数排斥(往外)的拉锯驻点 (★), λ_adv 高时退离中点甚至退出竞争——这正是危险头的用武之地。纯规则做市会被结构性逆选(PM 滞后 13s 是铁证), 但三条当下可观测的阈值规则(sharp-gap 拉单 + 事件新鲜度全撤 + book 陈旧不挂)无需模型即可挡掉 70% 有毒流, 救活 P1。激励做市化解了引擎1 的样本顾虑(结构性现金流不需要 walk-forward, 1-2 天 paper 验 α 即可)且**解除了引擎2 的"赶上线"过拟合压力**, 但引擎2 套利模型的 walk-forward 纪律一字不改。优先级: P1 规则做市(今天)→ P1.5 危险头(低样本)→ P2 套利模型(攒够样本)→ P3 序列模型。
