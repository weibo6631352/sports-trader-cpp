## §0 三句话先翻盘（操盘手对新事实的第一反应）

1. **激励池没有捅破我 round-1 的天花板，它换了一根天花板。** 我 round-1 的 $5-50/天天花板是【套利的】，受"流动性+覆盖+事件稀疏"三重压。激励是**另一条独立利润线**，它的天花板是【激励的】——受"pro-rata 稀释 + 逆向选择失血 + 资金占用"三重压。**不是把 $50 抬到 $500，是开了第二个池子。两个池子各有各的盖。**

2. **但激励这条线，作为操盘手我比套利更有信心它能稳定为正——前提是别裸做。** 套利要赌"进球后 PM 真的够本收敛"（G2 还没证实，命门没过）。激励做市赚的是**结构性返钱**，只要我"双边贴中点挂够 size 且不被扫穿"就拿钱，不依赖任何预测对不对。这是它最香的地方:**收入端确定性 >> 套利**。风险全在成本端（被扫），而成本端我有几十年防逆选的肌肉记忆。

3. **草案最大的盲点不是"逆选能不能扛"，是"P1 无模型先上做市"这句话本身。** 作为操盘手我明确告诉你:**裸做市（没有避险信号）在 in-play 盘上一晚被扫穿是必然不是可能。** 但草案有救——救法不是"等模型"，是"先在不会被扫穿的地方做"(极价区 + pregame 池 + 宽贴)。下面逐条拆。

## §1 激励做市的实战可行性 —— bet365 一跳，我的两个挂单会被怎么打

这是全场最实战的问题。我把"双边挂 BUY YES + BUY NO 贴中点"放到真实盘口里走一遍，看它怎么死、怎么活。

### 1.1 先把"双边做市"的机制说死（避免摆错盘）

Polymarket 二元市场 YES+NO≈1。激励要的"双边"是:**我同时挂一个 BUY YES 限价单（在 mid 下方）+ 一个 BUY NO 限价单（在 mid 下方）**。注意两个都是 BUY:

- BUY YES @ (mid_yes − δ)：我愿意便宜接 YES
- BUY NO @ (mid_no − δ) = 等价于 SELL YES @ (mid_yes + δ)：我愿意贵卖 YES

所以"双边 BUY YES + BUY NO"在 YES 价格轴上 = **我在 mid 两侧各挂一档:低位接、高位卖。这就是教科书做市(挂 bid + 挂 ask)。** verified doc §3 说两单共用同一 balance reserve（挂单总和 ≤ 可用余额）—— 这点很关键，意味着我双边名义敞口受单市场余额约束，不能无限堆。

**赚钱的两种路径，必须分清:**
- **路径 A（激励为主）:** 两单都不太成交，我只是"提供深度"挂在那，按分钟 sample 拿 pro-rata 激励。理想态是**挂着拿钱、尽量不成交**。
- **路径 B（spread 为辅）:** 两单偶尔都成交一轮（先被人扫了我的 ask 卖出 YES，又被人扫了我的 bid 买回 YES），我赚 2δ 的 round-trip spread + maker 零费。这是传统做市利润。

**操盘手第一个判断:** 在 Polymarket 体育盘，路径 B（赚 spread）在 in-play 几乎赚不到——因为成交是**单向到来的**(信息来了大家往一个方向扫)，我很少能两边都成交收口。**激励做市的真利润来自路径 A（拿激励），路径 B 是奢望。** 这反过来定义了我的目标:**我不是来赚 spread 的，我是来"挂着收租"的，而 spread 方向那一边的成交是我要竭力避免的成本（逆选）。**

### 1.2 bet365 一跳，哪个挂单被扫、亏多少 —— 走一遍实盘

场景:网球，盘中，主队（公众偏好方向）YES mid = 0.50，我贴中点双边做市。

```
我的挂单 (贴 ±2c, 假设拿激励):
  BUY YES @ 0.48   (size $200)   ← 我的 bid
  SELL YES @ 0.52  (= BUY NO @0.48, size $200)  ← 我的 ask
─────────────────────────────────────────
事件: 主队 break point 转化 (赢下关键一局)
t=0     真实事件
t=2s    bet365 in-play: 主队 fair 0.50 → 0.62 (跳 12c)
t=3s    场内有人 / 比我快的 bot 知道了 → 冲进 PM
t=3-13s PM 重定价中, mid 从 0.50 爬向 0.62
─────────────────────────────────────────
被扫的是哪个? → 我的 SELL YES @0.52 (ask 边)
  有人（散户追涨 or 比我快的 bot）穿价 0.52 吃掉我的 ask
  我以 0.52 卖出了 YES, 但新 fair 是 0.62
  → 我刚以 0.52 卖了一个值 0.62 的东西, 瞬间浮亏 10c × shares
  我那 $200 ask ≈ 385 shares → 浮亏 ≈ $38
我的 BUY YES @0.48 (bid 边)? → 没人来卖给我（谁会 0.48 卖一个值 0.62 的东西）
  → bid 边挂空, 我只剩一条裸的 short YES @0.52 仓位
```

**这就是逆向选择(adverse selection)的标准死法,操盘手的本行。** 关键洞察:

- **被扫的永远是"价格要去的那个方向"的那条腿。** 价格要涨 → 我的 ask 被吃（我被迫低卖）；价格要跌 → 我的 bid 被吃（我被迫高买）。**我总是被留在错的一边。**
- **另一条腿（对的方向那条）永远不会成交**，因为没人愿意把"要涨的东西便宜卖给我"。所以做市做不成对称 round-trip，**双边挂单在事件来临时退化成单边裸仓，而且是亏的那一边。**
- **单次逆选亏 10c × size**，而单分钟拿到的激励是多少?见 §2 算账 —— 远不到 10c × size。**一次被扫穿，吃掉几十分钟甚至几小时的激励。** 这就是裸做市一晚被扫穿的算术。

### 1.3 贴多紧才"既拿激励又不被扫爆" —— 操盘手的核心手感

这是激励做市能不能正期望的全部秘密。二次奖励 `S=((v−s)/v)²×b` 要我**贴近中点（s 小）**才拿高分；但贴越近，被扫时离新 fair 越远、亏越多。**这是一个紧贴拿高激励 vs 宽贴防逆选的最优化。**

操盘手不算二次函数，我用三个手感参数定贴多紧:

1. **波动率定底线宽度。** 贴的半价差 δ 必须 ≥ "我感知延迟内 mid 的典型移动"。我们端到端感知 3.1s（小袁），3.1s 内一个 break point 能让网球 mid 移 8-12c。**所以在"事件随时可能来"的盘，δ 至少要 6-8c 才不会一跳就被扫穿。但 6-8c 的 δ 在二次奖励里分已经很低了（如果 v=max_incentive_spread 只有 3-5c，我直接出局不计分）。** —— 这是第一个要命的矛盾:**in-play 高波动盘，防逆选要求的宽度 > 激励资格要求的窄度。两者打架。**

2. **事件密度定"敢不敢挂"。** 网球 break point、篮球每次得分、足球进球 —— 事件越密，我挂着的每一秒都在"等着被扫"。**事件密集的盘不适合常驻挂单做市，适合的是事件稀疏、价格平稳的盘。**

3. **撤单速度定"挂多久"。** 理论上事件来了我立刻撤单就不被扫。但:① 我感知要 3.1s，撤单要 25-60ms，**事件发生到我撤掉,至少 3.1s,这 3.1s 我的单是裸露的**；② verified doc §3 心跳 10s + 撤单要发 cancel —— 跨洋链路撤单本身有延迟；③ 更狠的:**激励按分钟 sample,我为了拿激励必须挂够时长,频繁撤挂 = 拿不到激励 + ToS 反操纵嫌疑(spoofing)。** 所以"事件来了秒撤"在拿激励的前提下是自相矛盾的 —— 我撤得勤就没激励,挂得久就被扫。

**结论(贴多紧):**
- **能拿激励又不被扫爆的盘,必须满足:δ_防逆选 ≤ v_激励资格,即"我需要的安全宽度 ≤ 激励允许的最大价差"。** 这只在**低波动 / 事件稀疏 / 价格已稳定**的盘成立。
- **in-play 高波动盘(网球决胜盘、篮球 Q4、足球进球期)做激励做市 = 送钱给扫单的人。** 这些恰恰是我 round-1 套利的甜区 —— **激励做市和套利的甜区是相反的(§5 详述)。**

### 1.4 极价区(mid<0.15)做市 vs 中价做市 —— 实战差异巨大

verified doc §2 有个关键机制我必须放大:**中点 <0.10 或 >0.90 时强制双边 `Q_min=min(Q_ne,Q_no)`,而 [0.10,0.90] 区间允许 c=3 的不对称(只挂单边拿 1/3 分)。** 这看似惩罚极价区(必须双边),但操盘手看到的是**极价区才是激励做市的真甜区**,原因:

| 维度 | 中价做市 (mid≈0.50) | 极价区做市 (mid<0.15 或 >0.85) |
|---|---|---|
| **逆选时的亏损** | 被扫亏 = \|新fair − 我成交价\|,中价波动空间大(能从0.5跳到0.7) | **极价区价格被"地板/天花板"夹住**,0.08 的 YES 最多跌到 0.001,涨空间也被0.15压。**单次逆选亏损天然受限** |
| **事件冲击** | 一个事件能让 mid 移 10-15c | 极价区(强弱已分)单个事件移动小(领先方 0.88→0.91,移 3c) |
| **被扫频率** | 中价 = 双方仍胶着 = 事件频繁改变方向 = 频繁被扫 | 极价区 = 胜负已大致定 = 事件少且小 = 挂着安稳 |
| **激励资格** | spread 窄(1c)→ v 小 → 容易出激励窗口 | 极价区 spread 可能宽,但只要在 v 内,二次分照拿 |
| **流动性深度** | 中价深(大家都在交易) | 极价区薄(但我们 size 本来就小,够) |
| **R-12 套利甜区重叠** | near_half 是套利禁区(BE 6.45c) | 极价区是套利甜区(BE 1.7c) —— **但做市和套利在极价区会打架,见 §3** |

**操盘手判断:激励做市的甜区 = 极价区(mid<0.15 / >0.85)+ 价格已稳定的盘。** 理由:逆选亏损被价格边界夹住(最致命的风险被结构性限制了)+ 事件冲击小 + 被扫频率低。**这跟我 round-1 直觉相反 —— 我本以为中价流动性厚适合做市,实战恰恰是极价区因为"亏损有上限"才敢裸挂。** 中价做市必须有避险模型(引擎3),极价区做市可以裸做。

**但极价区有个隐藏坑(操盘手提醒):极价区被扫"频率低但幅度可能极端"。** 一个 0.92 的领先方,如果突然被绝杀(网球决胜盘 break back、足球 90 分钟绝平),0.92 → 0.40,我挂在 0.90 的 bid 被扫,瞬间亏 50c。**低频尾部大亏。** 极价区做市要配"领先方崩盘"的尾部熔断(比分接近反转时立即全撤),这个比中价做市的避险还重要。

### 1.5 §1 小结 —— 激励做市实战可行,但只在窄窗口

激励做市**可行且收入端确定**,但安全运营窗口比草案想象的窄得多:
- **可裸做(无模型):** 极价区(mid<0.15/>0.85)+ 大联赛流动盘 + 配领先方崩盘尾部熔断。
- **必须有避险模型才能做:** 中价区(0.15-0.85)、in-play 高波动期。
- **绝不做:** near_half(0.35-0.65)in-play + 事件密集期(同时是套利甜区,资源该给套利)。

## §2 天花板重估 —— 激励 pro-rata 我们一天能实际分到多少

草案问"$5M/月 pro-rata 我们能分多少"。我用操盘手的方式算一笔保守账(数学精算归小梁/小袁,我给业务量级)。

### 2.1 先破一个幻觉:$5M/月 ÷ 30 = $16.7万/天,不是给我们的

$5M/月是**全平台所有体育电竞市场、所有做市商瓜分的总池**,而且**per game / 赛前盘中分池**。关键稀释链:

1. **per game 分池:** $5M 摊到一个月所有比赛。一天可能有几百上千场有激励的盘,单场单池可能只有几十到几百刀/天。
2. **pro-rata 被鲸鱼稀释:** 单池里 `我的Q / 全体Q`。专业做市商(Polymarket 上已有成熟 MM)挂的 size 是我们的几十上百倍。**我们 size 天花板是 sport_profile 实测的深度(网球 Late $3k、足球 $150-500、篮球 Late $1.2k)—— 这是被流动性钉死的,激励再大我也只能挂这么多。** 我挂 $200,鲸鱼挂 $20000,我分到的是 200/(200+20000+...) < 1%。
3. **二次奖励要贴中点:** 我若为防逆选宽贴(§1.3),s 大,二次分 ((v-s)/v)² 暴跌,**我那 <1% 的份额还要再打个折。**

### 2.2 保守量级估算(操盘手拍,待小梁精算)

用我们能安全裸做的范围(极价区 + 不被扫穿)反推:

```
假设(保守):
- 我们能稳定挂激励的盘: 网球(75%覆盖)极价区 + 篮球/棒球极价区, 同时约 20-40 个活跃盘
- 单盘我们能挂的 size (受流动性+余额约束): $100-300 双边
- 单盘单池日激励总额(per game pro-rata 后, 估): $20-100
- 我们在单池的份额(被鲸鱼稀释 + 宽贴打折): 0.5%-3%
─────────────────────────────────────
单盘日激励到手 = $20~100 × 0.5%~3% = $0.1 ~ $3 /盘/天
20-40 盘 → 日激励到手 ≈ $5 ~ $80 /天 (毛, 未扣逆选失血)
```

**减去逆选失血:** 如果避险没做好,在中价/in-play 被扫几次,单次亏 $10-38(§1.2),**一晚被扫 3 次就把当天激励全亏回去还倒贴。** 所以**净激励 = 毛激励 − 逆选失血**,而逆选失血完全取决于我们做市的纪律和避险:
- **裸做极价区(纪律好):** 逆选失血小,净激励 ≈ $5-60/天。
- **裸做中价(草案 P1 原样):** 逆选失血 > 毛激励,**净负**。

### 2.3 对比 round-1 套利 $5-50/天 —— 谁大,主引擎该是谁

| 维度 | 引擎1 激励做市 | 引擎2 事件套利(round-1) |
|---|---|---|
| **收入端确定性** | ✅ 高(挂着就拿,不赌预测) | ❌ 低(赌 G2 够本收敛,命门未过) |
| **毛量级** | $5-80/天(极价区裸做) | $5-50/天 |
| **覆盖面** | ✅ 全体育电竞(激励池覆盖广) | ❌ 仅 tennis/soccer 有 bet365 in-play |
| **不依赖预测精度** | ✅ 是(这是最大优点) | ❌ 否(需 G2 + 收敛预测) |
| **主风险** | 逆向选择失血(可控,本行) | 不收敛/反向事件(赌) |
| **资金占用** | 高(双边挂单常驻占余额) | 低(只在事件瞬间占用 10-15s) |
| **可立即上(paper)** | ✅ 极价区规则化可立即跑 | ❌ 要先建事件触发管道 + G2 |
| **天花板** | pro-rata 稀释 + 流动性 size | 流动性 + 覆盖 + 事件稀疏 |

**操盘手的主引擎判断(修正 round-1):**

> **激励做市应该是主引擎,事件套利降为"叠加在做市仓位上的择时增强"。**

理由(操盘手实战逻辑,不是为了讨好新事实):
1. **收入端确定性碾压。** 套利的 $5-50 是"如果 G2 过、如果收敛、如果抢得到"的条件期望;激励的 $5-80 是"只要挂着不被扫穿"的结构期望。**做交易,确定的小钱 > 不确定的大钱。**
2. **覆盖面碾压。** 套利只能在 tennis/soccer(有 bet365 in-play)做;激励池覆盖所有盘,**绕开了我 round-1 反复强调的"sharp 覆盖缺口"天花板(A1-3)。** 这是真正的解放。
3. **不赌命门。** 套利的命门 G2 还没过,把主引擎压在未证伪的假设上是操盘大忌。激励不需要 G2。
4. **但两者量级其实接近($5-80 vs $5-50)。** 所以更准确的说法是:**它们是两条并行的小现金流,合起来 $10-130/天量级,激励因确定性更高更适合做地基。** 草案叫"双引擎"是对的,我 round-1 把套利当唯一引擎是因为我不知道激励 —— **这点我认错。**

**但我要给老板泼一盆冷水(数字说话,公司铁律):无论哪个引擎,日量级都在两位数到三位数美元。** 北极星是年化 $5M(≈$1.4万/天)。$10-130/天离这个差 100 倍。**这两个引擎是"先证明系统能稳定赚正钱"的 MVP 引擎,不是 $5M 的答案。** $5M 的答案在"scale size(需要更多资金 + 更深盘)"和"覆盖更多盘"上,而 size 被流动性钉死 —— 这是结构性天花板,激励没有改变它。**别让"激励池 $5M/月"这个数字给人"我们能分很多"的错觉,pro-rata 后我们是池子里的小鱼。**

## §3 双引擎实战内耗 —— 同一个盘能不能并存

草案问得很准。这是操盘手最容易踩的坑:**两个策略在同一个市场互相吃单。** 逐个场景拆。

### 3.1 核心冲突:激励要"挂着别动",套利要"事件来了猛吃"

```
同一个网球盘, mid 0.50:
  引擎1 做市挂单: BUY YES @0.48 + SELL YES @0.52 (等激励)
  引擎2 套利待命: 监测 bet365, 等事件触发
─────────────────────────────────────
事件来了: 主队 break, bet365 fair 0.50→0.62
  引擎2 想干什么? → TAKER 穿价买 YES (抢在 PM 重定价前吃便宜 YES)
  引擎1 的挂单此刻是什么? → SELL YES @0.52 还挂着
─────────────────────────────────────
冲突点: 引擎2 要"买便宜 YES", 而市场上最便宜的 YES ask 之一
        就是引擎1 自己挂的 SELL YES @0.52!
  → 引擎2 可能吃掉引擎1 的单 (自成交 self-trade, 左手吃右手)
  → 或者引擎2 还没动手, 外部扫单者已经吃了引擎1 的 0.52 (引擎1 被逆选)
```

**这是真冲突,不是理论。** 两种坏结果:
1. **自成交(self-trade):** 引擎2 吃掉引擎1 的挂单 —— 白付不了 fee(maker 引擎1 零费、taker 引擎2 付费),但**等于自己跟自己换手,没意义还可能触发 ToS wash-trade 嫌疑(verified doc §4 待确认反操纵条款)。必须在下单层做 self-trade prevention(STP)。**
2. **引擎1 被外部逆选,引擎2 才反应过来:** 事件来了,引擎1 的 0.52 ask 先被外部扫(引擎1 浮亏),引擎2 这时才 taker 进场。**等于引擎1 替引擎2 当了第一个接盘的冤大头。**

### 3.2 操盘手的解法:同盘不同时,事件来临"切换模式"

真操盘台的做法不是"两个策略同时在一个盘上跑",是**一个盘在任一时刻只处于一种模式**:

```
盘的状态机 (单盘单一模式):
  [平静态] → 引擎1 做市挂双边, 收激励. 引擎2 待命监测.
  [事件触发] → ① 引擎1 立即全撤挂单 (避免被自己/被外部逆选扫)
              ② 切到 [套利态]: 引擎2 taker 进场吃错价
              ③ 套利仓平掉 + 价格重新稳定后 → 切回 [平静态], 引擎1 重新挂单
```

**关键:事件信号是两个引擎的共享触发器。** 同一个 Goalserve 事件闸口,对引擎1 是"撤单避险信号",对引擎2 是"进场信号"。**它们不是打架,是接力 —— 引擎1 在平静期收租,事件一来引擎1 让位、引擎2 上场抢钱,抢完引擎1 再回来收租。**

这恰好把 §1.3 的矛盾解决了:**引擎1 不需要在事件期硬扛逆选(因为它撤了),引擎2 不需要等模型(因为它就是吃事件错价)。** 两个引擎的弱点互相用对方的强项补:
- 引擎1 怕逆选 → 用引擎2 的事件闸口提前撤单避险(这就是草案说的"引擎3 避险",其实引擎2 的触发器本身就够当避险信号,不一定要单独的预测模型)。
- 引擎2 怕没流动性/没对手 → 平静期引擎1 挂的单本身增加了盘的深度(虽然事件来了要撤)。

### 3.3 但"撤单延迟"这个洞补不上(诚实交代)

接力模式的命门:**引擎1 从"感知事件"到"撤完单"有 3.1s 延迟(感知)+ 撤单链路延迟。这 3.1s 里引擎1 的单是裸露的,会被比我们快的人扫。** 这个洞工程上补不满(感知延迟是 Goalserve 2s 刷新钉死的)。操盘手的现实接受:
- **极价区做市,这 3.1s 裸露的亏损被价格边界夹住(§1.4),可接受。**
- **中价做市,这 3.1s 能被扫 10c,不可接受 → 所以中价做市必须靠预测模型"在事件发生前"就偏报价/收紧,不能靠事件后撤单。**

**这再次指向同一个结论:裸做(规则化)只能在极价区;中价要模型。** §1、§2、§3 三条路殊途同归。

### 3.4 资金/余额内耗

verified doc §3:同市场 YES+NO 挂单共用 balance reserve。引擎1 双边挂单占用余额,引擎2 事件来时要 taker 进场也要余额。**同盘两引擎抢余额。** 解法:接力模式天然解决 —— 引擎1 撤单时余额释放,引擎2 才进场,不重叠占用。**前提是撤单先于进场(状态机保证)。** 跨盘则需组合层 bankroll 分配(归小梁 Kelly / 老韩 RM)。

## §4 攻草案盲点 —— P1"无模型先上做市"敢不敢裸做

草案 P1:"引擎1 规则化做市(广,立即跑,赚激励,不需模型)。" 草案红队问 #4:"是否真可行,还是必须先有避逆选模型否则被扫爆?"

### 4.1 操盘手的直接回答:分区。中价裸做必被扫穿,极价区裸做可行。

**草案 P1 原话"无模型先上做市"如果不分区,是错的,会一晚被扫穿。** 但它有救,救法是把"无模型"限定在安全区:

| 做市区域 | 裸做(无模型)行不行 | 操盘手裁决 |
|---|---|---|
| **极价区 mid<0.15 / >0.85** | ✅ 行 | 逆选亏损被价格边界夹住(§1.4),配领先方崩盘尾部熔断即可裸做。**这是 P1 真正能跑的范围。** |
| **中价区 0.15-0.50 / 0.50-0.85** | ❌ 不行 | 单次被扫亏 5-10c,毛激励盖不住。**必须有"事件将至"的提前信号(引擎2 触发器或引擎3 模型)才能做。** |
| **near_half 0.35-0.65 in-play** | ❌❌ 绝不 | 波动最大、双方胶着事件最频繁、激励 spread 最窄(v 最小最易出窗)。裸做这里 = 自杀。 |
| **任何区的 pregame 池** | ✅ 行(最安全) | pregame qhl 长(>120s 实测)、无 in-play 事件冲击、价格慢漂。**这是裸做市最安全的地方,被严重低估了。** |

### 4.2 操盘手敢不敢裸做市?—— 敢,但只在两个地方,且配硬熔断

**我作为操盘手,敢裸做市(无避险模型)的地方只有两个:**
1. **极价区 in-play(mid<0.15/>0.85)** + 领先方崩盘尾部熔断(比分接近反转→全撤)。
2. **pregame 池(任何价位)** + 临场前 N 分钟全撤(进 in-play 前清场,因为 in-play 事件风险来了)。

**绝不裸做的地方:** 中价 in-play、near_half、事件密集期。这些地方"裸做一晚被扫穿"不是风险是必然 —— 我用 round-1 §5.1 的逆选死法担保这一点。

### 4.3 草案 P1 的修正建议

把草案 P1 从"引擎1 规则化做市(广,立即跑)"改为:

> **P1(修正):引擎1 规则化做市,首发限定【pregame 池 + in-play 极价区(mid<0.15/>0.85)】,配领先方崩盘 / 临场前全撤两个硬熔断。中价 in-play 做市等引擎3 避险模型(P3)就绪后才开。**

这样 P1 真的能"立即跑、赚激励、不被扫穿",且不依赖任何模型。**"广"要打折 —— 不是所有盘所有价位都能裸做,是"所有盘的安全区"能裸做。**

### 4.4 一个草案没提的实战风险:做市的"心跳/撤挂"运维负担

verified doc §3:每 10s 必须心跳否则撤单。做市是**常驻挂单**,意味着我们要 7×24(或至少赛事时段)维持几十个市场的双边挂单 + 每 10s 心跳 + 事件来了批量撤单。**这是套利(只在事件瞬间动手)完全没有的运维负担。** 跨洋链路(高延迟)+ WSS 心跳/重连(memory clob-wss-heartbeat 已修但仍是地基)—— **做市策略对系统在线率和链路稳定性的要求,比套利高一个数量级。** 一次 WSS 断线 30s 没重连,我几十个市场的单全被自动撤(没激励)或者更糟(断线时事件来了撤不掉单被扫穿)。**这是上激励做市前工程上必须压实的(归老周/小郑观测栈),操盘手不接这活但必须点名。**

## §5 甜区/禁区修正 + 收敛建议

### 5.1 激励做市的甜区/禁区 vs 套利的甜区/禁区 —— 关键发现:基本相反

| 价位区间 | 套利甜区?(round-1) | 激励做市甜区? | 操盘手解读 |
|---|---|---|---|
| **极价区 mid<0.15/>0.85** | ✅ 甜区(BE 1.7c) | ✅ 甜区(逆选夹住) | **唯一两者都甜的区** —— 但会打架(§3),靠状态机接力 |
| **中价 0.15-0.35 / 0.65-0.85** | △ 一般 | ⚠️ 需模型 | 套利可做,做市要避险 |
| **near_half 0.35-0.65** | ❌ 禁区(BE 6.45c) | ❌ 禁区(逆选最狠) | **两者都禁,理由不同但结论一致** |
| **pregame 池** | ❌ 非事件套利范畴 | ✅ 甜区(最安全裸做) | **激励做市独占的甜区,套利碰不到** |

**核心发现:套利甜区 = in-play 事件期(价格在动);激励做市甜区 = 价格平静期(没事件)。在时间轴上它们是相反的。** 同一个盘,平静期我做市收激励,事件期我撤单做套利。**这不是矛盾,是完美的时间分工 —— §3 的状态机接力正是利用了这个相反性。** 我 round-1 没看到这一层(因为不知道激励),现在看到了:**两个引擎在时间维度上天然互补,一个吃"静",一个吃"动"。**

按运动的甜区(综合两引擎):

| 运动 | 激励做市(静) | 事件套利(动) | 综合打法 |
|---|---|---|---|
| **Tennis(75%)** | ✅ 极价区+局间平静期+pregame | ✅ break/set point 事件 | **双引擎全开,主战场** |
| **Basketball** | ✅ 极价区(垃圾时间领先大) | ✅ 得分事件 | 双引擎,Q4 hot 期偏套利 |
| **Baseball** | ✅ 局间平静(得分稀疏=平静多) | ✅ 得分事件 | **棒球平静期长 → 激励做市尤其适合** |
| **Soccer** | △ 流动性薄($150-500)激励份额小 | △ 进球强但盘薄 | 小 size 双引擎,别期望大 |
| **Esports** | ❌ 流动性陷阱 | ❌ 同 | 暂不做(同 round-1) |
| **板球** | ❓ 无 profile | ❓ | 先确认覆盖(同 round-1) |

**棒球的新认识:** round-1 我把棒球归"事件套利好(得分稀疏冲击大)"。加上激励视角,**棒球的"得分稀疏"意味着"平静期特别长"—— 这恰恰是激励做市的理想环境(挂着收租很少被扫)。棒球可能是激励做市最舒服的运动。** 这是新事实带来的认知升级。

### 5.2 操盘手认同的最终打法(收敛建议)

**一句话:激励做市做地基(吃静、收确定的租)+ 事件套利做增强(吃动、抢不确定的错价)+ 单盘状态机接力切换,首发限安全区裸做,模型后置只为开中价。**

具体落地次序(操盘手版,修正草案优先级):

1. **P0 核实(同草案,补一条):**
   - ① in-play 进球后 PM 是否暂停撮合(套利命门,同草案)。
   - ② 流动性激励真实参数:`max_incentive_spread`(v)、`min_incentive_size`、in-game 乘数 b、pro-rata 我们实测能领多少(**这条是激励引擎的命门,等价于套利的 G2 —— 没实测激励到手额,"激励主引擎"也是假设**)。代码里目前零接入(grep 确认无 incentive 字段),要先接 CLOB rewards API 拉真参数。
   - ③ **ToS 反操纵条款**(verified doc §4 待确认):做市快速撤挂 + self-trade prevention + 双边贴中点是否触发 wash/spoofing 嫌疑。**这条不清不上做市 —— 违反 ToS 是 §8 红线(平台封号 = 全盘皆输)。**

2. **P1 激励做市规则化(修正:限安全区):** 首发 pregame 池 + in-play 极价区,配两个硬熔断(领先方崩盘 / 临场前全撤)。**这是真正能立即跑、赚确定激励、不被扫穿的范围。** 先 paper 跑,实测单盘激励到手额,验证 §2 的 $5-80/天 量级。

3. **P2 事件套利(同草案,但定位降为"做市仓位的事件期增强"):** 建事件触发管道(同时服务两引擎 —— 对做市是撤单信号,对套利是进场信号,一套管道两用)+ G2 验证。状态机接力(§3.2)落地,含 self-trade prevention。

4. **P3 引擎3 避险模型(定位收窄):** **只为"解锁中价做市"服务。** 极价区/pregame 裸做不需要它,中价 in-play 做市需要它(在事件前偏报价/收紧)。**别把它写成"双引擎必需的大脑",它是"开中价区的钥匙",不是地基。** 这样 P3 延后不阻塞 P1/P2。

5. **上线闸(同 round-1 + 补):** paper 净利/成本 > 1.5 + **激励净额(毛激励 − 逆选失血)实测为正** + 真钱开闸老韩 RM + 小白安全会签(§8.1)。

### 5.3 给老板的三句诚实话(数字说话)

1. **激励做市值得做主引擎,因为收入端确定 + 覆盖广 + 不赌命门 —— 但它的"主"是"地基稳",不是"量大"。** pro-rata 后我们是小鱼,日量级 $5-80,跟套利一个数量级。我 round-1 说套利是"补充策略"没错,但我没意识到激励是一条更稳的并行小现金流。**修正:两条小现金流,激励做地基(稳),套利做增强(冲),合计两位到三位数美元/天。**

2. **草案"无模型先上做市"分区后成立:极价区/pregame 裸做行,中价裸做必被扫穿。** 模型(引擎3)不是地基是"开中价的钥匙",可后置。

3. **离 $5M 北极星差 100 倍,激励池没改变这个 —— 天花板还是流动性 size(我们是池里小鱼)。** 这两个引擎是"证明系统能稳定赚正钱"的 MVP 答案,不是 $5M 答案。**别被 $5M/月激励池这个数字误导成"分蛋糕能分饱"。** 实话:先把 $50/天稳定赚到、净额为正、零踩 ToS 红线,比追大数靠谱。

## §7 一页纸结论(给老板,操盘手 round-2 定稿)

1. **主引擎修正为"激励做市(地基/吃静)+ 事件套利(增强/吃动)"双引擎,激励因收入端确定 + 覆盖广 + 不赌 G2 命门而更适合做地基。** 但两者量级接近($5-80 vs $5-50/天),都是 MVP 现金流,不是 $5M 答案。

2. **激励做市实战可行但安全窗口窄:** bet365 一跳,被扫的永远是"价格要去的方向"那条腿(我总被留在错的一边,单次亏 10c×size)。**裸做只能在极价区(逆选亏损被价格边界夹住)和 pregame 池;中价/near_half/事件密集期裸做必被扫穿。**

3. **双引擎不内耗,靠"单盘状态机接力":** 平静期引擎1 做市收激励,事件来临引擎1 全撤、引擎2 taker 进场抢错价,抢完切回。**套利甜区(动)和做市甜区(静)在时间轴上相反 —— 这是完美时间分工不是矛盾。** 必须做 self-trade prevention(防左手吃右手 + ToS wash 嫌疑)。

4. **草案 P1"无模型先上做市"分区后成立:** 限 pregame + in-play 极价区,配领先方崩盘 / 临场前全撤硬熔断。中价做市等引擎3。**引擎3 不是地基,是"开中价区的钥匙",可后置。**

5. **激励引擎的命门 = 实测 pro-rata 到手额(等价于套利的 G2):** 代码零接入,先接 CLOB rewards API 拉真参数(v/min_size/b)+ paper 实测净额(毛激励 − 逆选失血)为正才算成立。**别被 $5M/月误导,pro-rata 后我们是池里小鱼。**

6. **最高优先级是 ToS 反操纵核实:** 做市快速撤挂 + 双边贴中点 + STP 是否触发 wash/spoofing 嫌疑。**违反平台 ToS 是 §8 红线,封号 = 全盘皆输,不清不上做市。**

7. **棒球认知升级:** 得分稀疏 = 平静期长 = 激励做市最舒服的运动(挂着收租少被扫)。round-1 只看到它套利好,激励视角下它做市也好。
