## 2. 平台 ToS 红线 (Polymarket + Goalserve + vendor)

### 2.1 Polymarket ToS (摘 2026 Q1 版本, 实时为准)

**资格 (Eligibility)**
- 用户必须 18+
- 一人一账户, **禁止多账户** (后果: 全部余额没收)
- 不与 Polymarket 员工建立隐性关联 (代理 / 内推刷量)

**API / 速率限制** (技术细节 @老李)
- CLOB 公开 endpoint 软限 ~10 req/s, 鉴权 endpoint ~50 req/s
- WSS 连接数 & 订阅数有上限, 滥用导致 IP 封禁
- 禁止: 绕过限频 (多 IP 轮询同账户) / 抓取超额数据 / 复用 token 滥用

**资金 / 提现 (平台层 KYC 触发)**
- 入金: 仅 USDC (Polygon)
- 提现走链上, 大额由平台触发 KYC (我们配合, 不在内部维护 KYC 追踪)
- 账户冻结条件由平台决定, 我们的应对见 §7

### 2.2 Goalserve ToS / 数据使用 (商业 vendor, 细节 @小段)

- token 不得公开分享, 不得多账户共用 token
- 数据缓存仅供本系统决策, **不对外提供 / 不转售 / 不二次分发**
- 退订后立即清除缓存
- 抓取频率遵守订阅档位 (inplay / livescore / pregame 各有限)

### 2.3 商业 vendor 合同 (review SOP 见 §6)

- AWS / GCP / Alchemy / QuickNode / Goalserve 等付费 vendor
- 任何新签 / 续签 / 升级合同, 走 §6 review 流程
- 重点看: 数据 ownership / SLA / 退出条款 / 转售限制

## 3. 反操纵红线 (业务行为)

Polymarket ToS 明确禁止 (措辞接近 CFTC Rule 180.1), 与地域无关, 平台直接执法:

**R1 — 多账户操作**
我们只有一个 Polymarket 账户. 任何代码逻辑暗示"切换账户"都禁止.

**R2 — Wash Trading (自买自卖)**
同账户两侧挂单互吃, **绝对**禁止. 即使是"对冲测试"也走 testnet. 多策略并行下单需订单去重 + 反向单冷却期 (灰区 G1).

**R3 — Spoofing / Layering**
挂单必须有真实成交意图. 撤单率监控触发阈值要 alert. Maker rebate 挖矿如果只为刷量被视作 spoofing (灰区 G2), 必须有真实成交配对.

**R4 — Marking the Close / 操纵小盘**
收盘前刻意操纵结算价 / Prop 市场低流动性套利单笔规模硬上限 (灰区 G4).

**R5 — Insider Info / 未公开信息交易**
不得购买 / 接收未公开赛事信息 (内幕 / 作弊源 / 收买球员/裁判). Outright/Series 长持仓在赛事最后阶段注意信息源合规 (灰区 G3).

**R6 — 绕过速率限制**
多 IP 轮询同账户 / 伪造 header / 复用 token 滥用 — 直接踩 §2.1 ToS, 后果是 IP 封 + 账户审查.

(原 v1 R4 美国元素 / R5 OFAC 已撤; R8 私钥明文落盘合并至 §5 内部数据安全; R9 数据转售合并至 §2.2 Goalserve / §4 数据使用; R10 公开宣传合并至 §4; R11 跨链桥 / R12 AI agent 提币合并至 §5 内部安全 + 老叶链上规范)

## 4. 数据使用红线 (reselling / 公开 / 内部)

**Polymarket 数据**
- gamma / clob / data REST + WSS: 个人交易使用 OK
- 禁止: 提供数据 API 服务 / 转卖第三方 / 公开 dashboard 含实时报价
- 抓取频率不超过 ToS 速率限制 (§2.1)

**Goalserve 数据**
- 见 §2.2, reselling 边界严守

**回测数据来源**
- 历史快照优先官方 archived endpoint, 第三方爬虫源可能违 ToS (灰区 G7)
- 本地缓存超过 7 天 + 二次分发 = 数据转售红线

**不公开宣传 / 不拉新**
- 不发推 / 不开 Discord / 不做策略服务 / 不做"信号收费"业务
- 个人项目身份, 维持 low-profile

**Contributors 个人信息**
- 邮箱 / 钱包地址仅项目内部使用, 不对外披露 (内部约束, 与 GDPR/PIPL 主体责任无关)

## 5. 内部审计完整性 + 数据安全 (与地域无关)

**审计完整性 (老唐 schema)**: 所有交易决策 / 下单 / 撤单 / 提币审批走 BLAKE3 链式 audit log, 保留 90 天加密存储, schema 变更需老唐 + 老黄双签.

**数据安全 (老沈 / 安全官实施)**: TLS / cert pin / IPC 鉴权; 日志**不得**含私钥 / API secret / KYC 原文; 私钥 mlock / MADV_DONTDUMP / SecureBuffer / 审批阈值 / HA (老孙 v5); 提币 = 人工确认 + 多签, AI agent **不得**拥有提币权限.

**AI agent 决策边界**: agent 自动下单 OK, **不得**自动调高仓位上限 / 改风控参数 (原灰区 G6 升硬红线), 边界写死代码不通过 config 旁路.

(老黄管 legal 边界, 实施归安全官 / 审计官, 见附录 A)

## 7. 未来迁合规地区触发点

**当前立场**: "未决" 姿态, 不为未定主体提前规划地域合规.

**触发节点 (任一满足即启动主体注册地评估)**:
- 盈利稳定 (连续 6 月正收益 + 提币累计 > $100k)
- 资金规模到位 (老雷决定外部募资 / 公司化)

**触发后流程 (90 天立项)**: 老雷定候选注册地 (开曼 / BVI / 瑞士 / 新加坡, 未定) → 外部律所做正式 jurisdictional review → 重新激活 v1 §2/§3/§6/§8 撤销项 + 据当地法重定义 → 钱包 / KMS / Shamir 地理重布局 (与老孙 / 老沈协同) → 全员重新签收 (届时强制).
